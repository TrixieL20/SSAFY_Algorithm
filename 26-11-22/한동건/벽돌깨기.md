# 접근 방법 / 핵심 아이디어

구슬 개수 N, 너비,높이 W, H의 최대 값이 4, 12, 15로 작아서,
모든 구슬을 각 위치마다 다 떨어뜨려서 젤 작은 블록을 구해야겠다 생각했음.

DFS 기반 모든 구슬을 모든 열에 떨어뜨리는 완전탐색 + BFS 기반 연쇄 폭발 시뮬레이션 으로 접근하였다.




<br>

# 시간복잡도
O(W^N × H×W)

1. 재귀 트리 노드 수
구슬마다 W개의 선택지가 있으니 깊이 k에서 노드는 W^k개
- 전체 노드 = W + W² + … + W^N ≈ W^N × W/(W−1)
- W=12, N=4 대입: 12 + 144 + 1,728 + 20,736 = 22,620개

2. 노드 하나에서 하는 일
3. 
| 작업 | 비용 | 이유 |
|---|---|---|
| `clone()` 복사 | O(HW) | 격자 전체 복사 |
| `dropBall` | O(H) | 한 열만 위에서 아래로 탐색 |
| `crush` | O(HW × P) | 각 칸은 최대 한 번만 깨짐. 깨질 때 큐에 최대 4(P−1)개를 넣는데, P는 블록 숫자의 최댓값이라 9 이하인 상수 → 사실상 O(HW) |
| `fallBlock` | O(HW) | 모든 칸을 한 번씩 훑음 |

노드당 O(HW) = 180에 상수배가 붙음

3. 곱하면

22,620 × 180 × (복사·폭발·낙하로 대략 3배) ≈ 1.2 × 10⁷

# 어려웠던 점 / 배운점

호흡이 너무 길었다.

이 부분은 끝까지 구현해내서 기분 좋았다

grid를 각 dfs마다 진입했을때의 grid로 복구해야하는데 뒤늦게 디버그 한다고 시간 좀 썼었다.
기존 배열을 원복하는 문제는 좀 풀었었는데 뒤늦게 떠올라가지고.. 다음엔 바로 구현하자
