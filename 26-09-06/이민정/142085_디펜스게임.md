# 접근 방법

`n+1 카드게임`을 풀면서 진행되는 라운드에 따라 낼 수 있는 최적의 수가 결정되는데 결국 진행할 수 있는 라운드를 구하는 것이어서 애를 먹었었다.

다른 분들의 답을 보니 결국 코인은 **결국 어디까지의 카드를 볼 것인가**를 정해주는 요소였고 그리디로 쉽게 풀 수 있었다.

그래서 이 문제에서도 비슷하게 `k`가 **현재 판단할 수 있는 라운드의 범위를 늘려주는 역할**을 한다고 생각했다.

무적권은 최대 `k`번 사용할 수 있으므로 `k`개의 라운드를 무적권으로 넘길 수 있다.

하지만 훨씬 많은 수의 적이 라운드를 진행하며 등장할 수 있으므로 **무적권은 적의 수가 많은 라운드에 사용하는 것이 유리하다.**

결국 무적권을 사용할 최적의 라운드는 회차가 진행될 수록 바뀐다.

그래서 이러한 경우를 잘 반영할 수 있는 자료구조가 무엇일까를 고민하다 priority queue를 사용해서 큰 k개는 어짜피 무적권을 사용할거니까 무시하고 병사 수를 사용해서 처리하는 경우만 따지자고 생각했다.

따라서 처음 `k`개의 적을 `PriorityQueue`에 넣어두고 이후 적을 하나씩 추가하면서 다음과 같이 처리했다.

1. 처음 `k`개의 적을 우선순위 큐에 넣는다.

### 여기서부터 반복
2. 다음 라운드의 적을 하나 추가한다.
3. 현재 `k + 1`개의 적 중 **가장 작은 적**을 병력으로 처치한다.
4. 가장 작은 적을 처치할 수 있다면 `n`에서 차감하고 다음 라운드로 진행한다.
5. 가장 작은 적조차 처치할 수 없다면 현재 우선순위 큐에 있는 적들은 모두 그보다 크기 때문에 더 이상 병력으로 처치할 수 없다.

<br>

6. 따라서 해당 시점부터는 남아 있는 적 중 최대 `k`개를 무적권으로 넘길 수 있으므로 종료한다.

즉, **작은 적부터 병력으로 처리하고 큰 적을 무적권 후보로 남겨두는 방식**이다.

<br>

# 자료구조

## `PriorityQueue<Integer>`

```java
Queue<Integer> pq = new PriorityQueue<>();
```

Java의 `PriorityQueue`는 기본적으로 **최소 힙**이므로 가장 작은 값이 `poll()`된다.

이 문제에서는 현재 판단할 수 있는 `k + 1`개의 적 중 **가장 작은 적을 병력으로 처리**하고 싶기 때문에 최소 힙을 사용했다.

```java
pq.add(enemy[idx++]);

int enemyCnt = pq.poll();
```

`PriorityQueue`의 크기는 항상 최대 `k`이므로 삽입과 삭제의 시간복잡도는 `O(log K)`이다.

<br>

# 핵심 아이디어

### 1. 처음 `k`개의 적을 우선순위 큐에 저장

```java
for (int i = 0; i < Math.min(enemy.length, k); i++) {
    pq.add(enemy[i]);
}
```

처음 `k`개의 라운드는 무적권으로 넘길 수 있는 후보라고 생각한다.

단, `k`가 `enemy.length`보다 클 수 있기 때문에 `Math.min(enemy.length, k)`를 사용해야 한다.

### 2. 다음 적을 하나 추가하고 가장 작은 적을 처치

```java
if (idx < enemy.length) {
    pq.add(enemy[idx++]);
}

int enemyCnt = pq.poll();
```

이렇게 하면 현재 `k + 1`개의 적 중 가장 작은 적을 병력으로 처치하게 된다.

왜 가장 작은 적을 처치할까?

무적권은 나중에 사용한다고 생각하면 된다.

현재 적들 중 작은 적을 병력으로 처리하고 **큰 적을 남겨두어야**, 이후 무적권을 사용할 때 더 많은 병력을 절약할 수 있다.

```text
작은 적 → 병력으로 처리
큰 적   → 무적권 후보로 유지
```

### 3. 가장 작은 적도 처치할 수 없다면 종료

```java
if (n - enemyCnt < 0) {
    pq.add(enemyCnt);
    break;
}
```

현재 `PriorityQueue`에서 가장 작은 적조차 병력으로 처치할 수 없다면

가장 작은 적도 못 잡음

↓

나머지 적들은 모두 더 큼

↓

병력으로 잡을 수 있는 적이 없음

↓

남은 적은 무적권으로 처리

따라서 이 시점에서는 더 이상 병력으로 진행할 수 없으므로 `while`을 종료한다.

여기서 중요한 부분이 `pq.add(enemyCnt)`이다.

`poll()`로 꺼낸 적을 다시 넣어주는 이유는 **이 적 역시 이후 무적권을 사용할 수 있는 대상이기 때문**이다.

복원하지 않으면 `pq.size()`가 실제 남아 있는 적의 수보다 하나 작아지게 된다.

### 4. 마지막에 무적권으로 처리할 수 있는 라운드 수를 추가

```java
if (!pq.isEmpty()) {
    answer += Math.min(pq.size(), k);
}
```

`while`문에서는 **병력으로 처치할 수 있는 라운드 수**를 계산한다.

그 이후에는 남아 있는 적을 무적권으로 처리할 수 있다.

하지만 무적권은 최대 `k`개이므로 `Math.min(pq.size(), k)`만큼만 추가해야 한다.

```text
남은 적 = 3
남은 무적권 = 5
```

5라운드를 진행할 수 있는 것이 아니라, 남은 적이 3개뿐이므로 **3라운드**만 추가할 수 있다.

```text
남은 적 = 5
남은 무적권 = 2
```

**2라운드**만 추가할 수 있다.

# 시간복잡도

`PriorityQueue`의 크기는 최대 `k`이다.

각 라운드마다 적을 `add()`하고 `poll()`하므로 각각 `O(log K)`가 걸린다.

전체 적의 수를 `N`이라고 하면 시간복잡도는 다음과 같다.

```text
O(N log K)
```

공간복잡도는 우선순위 큐에 최대 `K`개의 적을 저장

```text
O(K)
```

<br>

# 배운 점

* `PriorityQueue`를 사용한다고 해서 무조건 `O(N log N)`인 것은 아니다.
  * 실제 우선순위 큐의 크기가 `K`로 제한되어 있다면 `add`, `poll`은 `O(log K)`가 된다.
  * 따라서 이 풀이에서는 `O(N log K)`로 볼 수 있다.
* 무적권을 단순히 처음 `K`개의 라운드에 사용하는 것이 아니라 **어떤 적에게 무적권을 사용하는 것이 가장 유리한지**를 생각해야 한다.
* 현재까지 접근 가능한 적들 중 작은 적을 병력으로 처리하고 큰 적을 남겨두는 방식으로 그리디하게 해결할 수 있었다.

<br>

# 실수한 부분

### 1. `k > enemy.length`인 경우를 고려하지 않음

처음에는 다음과 같이 작성했다.

```java
for (int i = 0; i < k; i++) {
    pq.add(enemy[i]);
}
```

그런데 `k`가 전체 라운드 수보다 클 수 있다.


```text
enemy.length = 3
k = 5
```

`enemy[3]`부터 존재하지 않기 때문에 `ArrayIndexOutOfBoundsException`이 발생한다.

따라서 아래와 같이 수정했다.

```java
for (int i = 0; i < Math.min(enemy.length, k); i++) {
    pq.add(enemy[i]);
}
```

### 2. 꺼낸 적을 다시 넣어야 하는 것을 놓침

```java
int enemyCnt = pq.poll();

if (n - enemyCnt < 0) {
    break;
}
```
다음과 같이 가장 작은 적을 꺼낸 후, 바로 종료하면 `pq`에서 적 하나가 사라진 상태가 된다.

하지만 이 적도 병력으로 처치할 수 없었을 뿐, **무적권을 사용하면 처치할 수 있는 적**이다.

따라서 `pq.add(enemyCnt);`로 다시 복원해야 한다.

### 3. 남은 적과 무적권 중 작은 값을 더해야 함

처음에는 마지막에 무조건 `k`를 더하면 된다고 생각했다.

하지만 남은 적보다 무적권이 많을 수도 있다.

```text
남은 적 = 2
k = 5
```

최대 5라운드가 아니라 2라운드만 진행할 수 있다.

따라서 `answer += Math.min(pq.size(), k);`로 처리했다.
