# 접근 방법

- 곡을 순회하며 장르별 총 재생수(totalPlays)와 장르별 [재생수, 인덱스] 목록(genreSongs)을 동시에 구성
- 장르 목록을 총 재생수 내림차순으로 정렬해 "어떤 장르부터 수록할지" 순서를 확정
- 각 장르 내부는 (재생수 내림차순, 동점 시 인덱스 오름차순)으로 정렬한 뒤 앞에서 최대 2곡만 채택

<br>

# 핵심 아이디어

- 장르의 우선순위(총 재생수)와 장르 내 곡의 우선순위(개별 재생수)는 서로 다른 기준이므로, 애초에 자료구조를 두 개(totalPlays, genreSongs)로 분리해서 집계해야 헷갈리지 않음
- 장르 내 정렬에서 "재생수 같으면 인덱스 오름차순"을 빼먹기 쉬운데, 문제 조건 3번이 이걸 명시하고 있어서 Comparator에 반드시 tie-break 조건을 넣어야 함

<br>

# 시간복잡도

- N = genres.length, G = 장르 종류 수 (G ≤ N)
- 곡 순회하며 집계: O(N)
- 장르 목록 정렬: O(G log G)
- 장르별 내부 정렬 총합: O(N log N) (각 장르 곡 수의 합이 N이므로)
- 전체 O(N log N)

<br>

# 어려웠던 점 / 배운점

처음에 접근했을때, 아직까지도 자바의 자료구조를 유연하게 다루지못해 힘들었다.
자료구조들을 만들고 또 나온 리턴으로 값을 계속 쌓아가면 내가 정말 잘구하고 있는지 의심이 들었다

제출한 풀이는 다른 풀이를 참고했다.
map,set 자료구조 데이터를 활용하는 메서드나, 어떻게까지 쓸 수 있는지 익숙해져야 이런 구현 문제를 해결할 수잇을거같다.
