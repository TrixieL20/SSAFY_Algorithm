# 접근 방법 / 핵심 아이디어

처음에는 ArrayList에 지금까지 나온 적의 수를 저장하고, 병사가 부족할 때마다 반복문으로 최댓값을 찾는 방식으로 구현했습니다.
하지만 매번 최댓값을 찾기 위해 리스트 전체를 탐색하면 최악의 경우 O(N²)의 시간복잡도가 발생하여 시간초과가 발생했습니다.
따라서 지금까지 등장한 적 중 최댓값을 빠르게 찾기 위해 최대 힙 PriorityQueue를 사용했습니다.

각 라운드에서는 다음과 같이 처리했습니다.

1. 현재 라운드의 적을 병사로 막았다고 가정하여 n -= enemy[i]
2. 현재 적의 수를 최대 힙에 저장
3. 병사가 부족 -> 무적권이 남아 있다면 
   - 지금까지 가장 적이 많았던 라운드를 poll()하여 무적권을 사용한 것으로 변경 
   - 해당 라운드에서 사용했던 병사를 다시 더해줌
4. 병사가 부족 -> 무적권도 없다면 현재 라운드에서 종료
<br>

# 시간복잡도

O(N log N)

<br>

# 어려웠던 점 / 배운점

처음에는 우선순위 큐가 익숙하지 않아 ArrayList에 적의 수를 저장하고, 병사가 부족할 때마다 반복문을 돌면서 가장 큰 값을 찾는 방식으로 구현했습니다.
로직 자체는 맞았지만 enemy의 길이가 최대 100만이기 때문에 최악의 경우 매번 리스트 전체를 탐색하게 되어 시간초과가 발생했습니다.
이번 문제를 통해 최댓값이나 최솟값을 반복적으로 찾아야 하는 경우 PriorityQueue를 활용할 수 있다는 점을 배웠습니다.
