# 접근 방법

* 광물은 **반드시 주어진 순서대로 캐야 하고** 한 번 곡괭이를 선택하면 최대 5개의 광물을 캘 수 있으므로 먼저 캘 수 있는 광물의 개수를 계산한 뒤 광물을 **5개씩 하나의 그룹으로 나누었다.**
* 각 그룹에 포함된 다이아몬드, 철, 돌의 개수를 저장하고 **다이아몬드 → 철 → 돌의 개수가 많은 순서**로 정렬했다.
* 이후 피로도가 적게 드는 다이아 곡괭이부터 철, 돌 곡괭이 순서로 사용하도록 했다.

처음에는 왜 이렇게 단순하게 정렬해서 풀 수 있는지 고민했는데 각 곡괭이의 피로도 차이가 일정한 배수 관계를 가진다는 점을 이용할 수 있었다.

예를 들어 철 곡괭이와 다이아 곡괭이의 차이는 다이아몬드를 캘 때 가장 크고 돌 곡괭이 역시 다이아몬드와 철을 캘 때 피로도가 크게 증가한다.

결국 **피로도가 많이 발생하는 광물이 많은 그룹에 좋은 곡괭이를 먼저 사용하는 것이 항상 유리하므로** 각 그룹을 중요도 순으로 정렬한 뒤 좋은 곡괭이부터 사용하는 그리디 방식으로 해결할 수 있었다.

## 자료구조

* `int[] picks`

  * 각 곡괭이의 개수를 저장
  
* `int[][] bundles`

  * 광물을 5개씩 나눈 그룹
  * 각 그룹별로 다이아몬드, 철, 돌의 개수를 저장

<br>

# 핵심 아이디어

* 한 번 선택한 곡괭이로 최대 5개의 광물을 캐야 하므로 광물을 먼저 **5개 단위로 묶는다.**

* 가지고 있는 곡괭이로 캘 수 있는 광물의 개수는 제한되어 있으므로 전체 광물이 아니라 실제로 캘 수 있는 범위까지만 확인한다.

```text
캘 수 있는 광물 개수 = min(전체 곡괭이 개수 × 5, 전체 광물 개수)
```

* 각 5개 그룹에서 다이아몬드, 철, 돌의 개수를 구한다.

* 이후 각 그룹을 다음 우선순위로 정렬한다.

```text
다이아몬드 개수 ↓
철 개수 ↓
돌 개수 ↓
```

* 피로도가 크게 발생하는 광물이 많은 그룹일수록 좋은 곡괭이를 사용하는 것이 유리하므로 다이아 곡괭이 → 철 곡괭이 → 돌 곡괭이 순서대로 사용한다.

이 방식이 가능한 이유는 광물별 피로도가 곡괭이가 나빠질수록 피로도가 일정한 비율로 증가하기 때문이다.

예를 들어 철 곡괭이에서 다이아몬드 하나를 캐는 피로도 `5`는 돌 곡괭이에서 철 하나를 캐는 피로도 `5`와 같고 돌 곡괭이에서 다이아몬드를 캐는 피로도 `25`는 이러한 차이를 더 크게 만든다.

따라서 **다이아몬드가 많은 그룹 → 철이 많은 그룹 → 돌이 많은 그룹 순으로 좋은 곡괭이를 배정하는 것이 최소 피로도를 만들 수 있다.**

<br>

# 시간복잡도

광물을 최대 `N`개

* 광물 그룹 생성 : `O(N)`
* 그룹 정렬 : `O(N log N)`
* 각 그룹별 피로도 계산 : `O(N)`


전체 시간복잡도

```text
O(N log N)
```

<br>

# 배운 점

* 곡괭이로 캐는 최대 개수가 5개로 정해져 있다는 점을 이용해 5개 단위로 문제를 나눌 수 있었다.
* 각 그룹을 비교할 때 단순히 피로도를 직접 계산해서 비교하는 것이 아니라 **다이아몬드 → 철 → 돌의 개수 순으로 정렬해도 되는 이유를 피로도 관계를 통해 확인할 수 있었다.**
* 풀이 논리와 그리디 선택이 가능한 이유는 의사코드를 작성하면서 여러 예시를 직접 만들어 검증했다.

<br>

# 실수한 부분

풀이 자체의 논리와 그리디 선택이 가능한 이유는 여러 예시를 만들어 의사코드로 충분히 검증했지만 마지막 피로도 계산 부분은 비교적 단순하다고 생각해서 의사코드를 대충 작성하고 바로 코드로 옮겼다.

그 과정에서 조건이나 계산 과정에서 조금씩 놓치는 부분이 생겼고 생각보다 구현에 시간이 오래 걸렸다.

앞으로는 **핵심 알고리즘뿐만 아니라 실제 구현 흐름까지 어느 정도 의사코드로 정리한 뒤 코드를 작성하는 습관이 필요하다고 느꼈다.**
