# 접근 방법

- 각 점수마다 라이언이 **해당 점수를 가져가는 경우 / 포기하는 경우** 두 가지로 나누어 DFS 탐색을 진행했다.
- 라이언이 특정 점수를 가져가려면 어피치보다 화살을 많이 맞혀야 하므로 `apeach[idx] + 1`개의 화살만 사용하면 된다.
- 모든 점수에 대한 선택이 끝나면 라이언과 어피치의 점수를 계산하여 가장 큰 점수 차이를 만드는 경우를 저장한다.
- 화살이 남은 경우에는 점수 결과에 영향을 주지 않도록 **0점에 남은 화살을 모두 배치**한다.
- 최대 점수 차이가 같은 경우에는 문제 조건에 따라 **더 낮은 점수를 많이 맞힌 경우**를 정답으로 선택한다.

## 자료구조

- `int[] apeach` : 어피치의 점수별 화살 개수
- `int[] ryan` : 현재 DFS에서 만들어진 라이언의 화살 배치
- `int[] answer` : 최종적으로 선택된 라이언의 화살 배치
- `int maxDiff` : 현재까지 발견한 라이언과 어피치의 최대 점수 차이

# 핵심 아이디어

### 1. 각 점수마다 선택 / 선택하지 않기

각 점수에서 라이언에게 필요한 선택은 두 가지이다.
1. 현재 정수를 가져가는 경우
2. 현재 점수를 포기하는 경우
특정 점수를 얻기 위해 어피치보다 훨씬 많은 화살을 사용할 필요는 없다.
예를 들어 어피치가 10점에 2발을 맞혔다면 라이언은 3발만 맞히면 10점을 가져갈 수 있다.
따라서 각 점수마다

- `apeach[idx] + 1`발을 사용하여 점수를 가져간다.
- 화살을 사용하지 않고 점수를 포기한다.

두 경우만 탐색하면 된다.

### 2. 백트래킹

점수를 가져가는 경우 `ryan[idx]`에 화살을 배치한 뒤 다음 DFS를 호출한다.

탐색이 끝나면 다음 경우의 탐색에 영향을 주지 않도록 다시 `0`으로 되돌린다.


이 과정을 통해 하나의 `ryan` 배열을 사용하면서 모든 화살 배치 경우를 탐색할 수 있다.

### 3. 남은 화살은 0점에 배치

모든 점수에 대한 선택이 끝났지만 화살이 남아 있을 수 있다.

문제에서는 라이언이 `n`개의 화살을 모두 사용해야 하므로 남은 화살을 0점에 배치한다.



0점은 승패의 점수 차이에 영향을 주지 않으므로 남은 화살을 처리하기 적절하다.

### 4. 점수 계산

`info` 배열의 인덱스 `i`는 실제로 `10 - i`점을 의미한다.

```text
index :  0  1  2  3 ... 10
score : 10  9  8  7 ...  0
```

둘 다 해당 점수에 화살을 맞히지 않았다면 아무도 점수를 얻지 않는다.

그 외에는 라이언이 어피치보다 많이 맞혔다면 라이언이 점수를 얻고, 그렇지 않으면 어피치가 점수를 얻는다.



### 5. 점수 차이가 같다면 낮은 점수부터 비교

문제에서는 최대 점수 차이가 같은 방법이 여러 개라면 **더 낮은 점수를 많이 맞힌 경우**를 반환해야 한다.

배열의 뒤쪽으로 갈수록 낮은 점수이므로 `10 → 0` 인덱스 순서로 비교한다.



예를 들어 두 결과가 다음과 같다면

```text
A = [0, 0, 0, ..., 2, 1]
B = [0, 0, 0, ..., 1, 2]
```

0점에 더 많은 화살을 맞힌 `B`가 우선된다.

<br>

# 시간복잡도

`O(2^11 × 11)`

점수는 10점부터 0점까지 총 11개이고, 각 점수마다

- 점수를 가져간다.
- 점수를 포기한다.

두 가지 선택이 존재하므로 최대 `2^11`개의 경우를 탐색한다.

각 경우마다 최대 11개의 점수를 확인하여 라이언과 어피치의 점수를 계산하므로 전체 시간복잡도는

```text
O(2^11 × 11)
```

이다.

점수 구간이 11개로 고정되어 있기 때문에 충분히 빠르게 탐색할 수 있다.

<br>

# 배운 점

- 각 원소마다 **선택 / 선택하지 않기**의 두 가지 경우가 존재하면 부분집합 형태의 DFS를 생각할 수 있다.
- DFS에서 배열의 값을 변경했다면 재귀 호출이 끝난 후 값을 원래 상태로 되돌리는 **백트래킹**이 필요하다.
- 특정 점수를 얻는 것이 목적이라면 필요한 최소 화살인 `apeach[idx] + 1`개만 사용하는 것으로 탐색 범위를 줄일 수 있다.
- 단순히 최댓값만 찾는 문제가 아니라 **동점일 때의 추가 조건**까지 고려하여 정답을 갱신해야 한다.

<br>

# 실수한 부분

- `info[i]`의 인덱스 자체가 점수가 아니라 실제 점수는 `10 - i`라는 점을 주의해야 한다.
- 어피치와 라이언이 모두 0발인 점수는 어피치가 가져가는 것이 아니라 **아무도 점수를 얻지 않는다.**
- 라이언이 어피치와 같은 개수의 화살을 맞히면 어피치가 해당 점수를 가져가기 때문에 라이언은 반드시 `apeach[idx] + 1`발을 맞혀야 한다.
- 최대 점수 차이가 같을 때 단순히 처음 발견한 경우를 사용하면 안 되고, **0점부터 낮은 점수 순서로 화살 개수를 비교**해야 한다.
- DFS 종료 시 화살이 남았다면 남은 화살까지 정답 배열에 포함해야 한다.
