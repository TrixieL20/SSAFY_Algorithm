# 문제 정보

| 항목 | 내용 |
| ----- | ----- |
| 문제 이름 | 햄버거 다이어트 |
| 난이도 | D3 |
| 플랫폼 | SWEA |
| 유형 | DFS, 백트래킹, 부분집합, 완전탐색 |

<br>

# 접근 방법

- 각 재료마다 **선택하는 경우 / 선택하지 않는 경우** 두 가지로 나누어 DFS 탐색을 진행한다.
- DFS를 진행하면서 현재까지 선택한 재료의 **맛 점수 합과 칼로리 합**을 함께 관리한다.
- 칼로리 합이 제한 칼로리 `L`을 초과하면 해당 조합은 정답이 될 수 없으므로 더 이상 탐색하지 않고 종료한다.
- 모든 재료를 확인했을 때 현재 맛 점수와 기존 최대 맛 점수를 비교하여 최댓값을 갱신한다.
- 최종적으로 제한 칼로리를 넘지 않는 조합 중 가장 높은 맛 점수를 출력한다.

## 자료구조

- `int[] score` : 각 재료의 맛 점수를 저장하는 배열
- `int[] calorie` : 각 재료의 칼로리를 저장하는 배열
- `int maxScore` : 현재까지 찾은 최대 맛 점수
- `int N` : 재료의 개수
- `int L` : 제한 칼로리

<br>

# 핵심 아이디어

### 1. 각 재료마다 선택 / 선택하지 않기

재료 하나를 확인할 때 가능한 경우는 두 가지이다.

- 현재 재료를 햄버거에 넣는다.
- 현재 재료를 햄버거에 넣지 않는다.

따라서 각 재료마다 두 갈래로 DFS를 진행하면 모든 재료 조합을 확인할 수 있다.

예를 들어 재료가 A, B, C 세 개라면 다음과 같은 방식으로 탐색한다.

```text
A 선택
├─ B 선택
│  ├─ C 선택
│  └─ C 선택 X
└─ B 선택 X
   ├─ C 선택
   └─ C 선택 X

A 선택 X
├─ B 선택
│  ├─ C 선택
│  └─ C 선택 X
└─ B 선택 X
   ├─ C 선택
   └─ C 선택 X
```

즉, **N개의 원소 각각에 대해 선택/미선택을 결정하는 부분집합 탐색 문제**로 볼 수 있다.

### 2. DFS에서 현재 상태 함께 전달

DFS를 호출할 때 다음 세 가지 정보를 관리한다.

- `idx` : 현재 확인하고 있는 재료의 위치
- `sumScore` : 지금까지 선택한 재료들의 맛 점수 합
- `sumCalorie` : 지금까지 선택한 재료들의 칼로리 합

현재 재료를 선택한다면 맛 점수와 칼로리를 더하고, 선택하지 않는다면 현재 값을 그대로 유지한 채 다음 재료로 이동한다.

### 3. 칼로리 제한을 이용한 가지치기

현재까지 선택한 재료들의 칼로리 합이 `L`을 초과했다면 이후 어떤 재료를 선택하더라도 이미 제한 조건을 만족할 수 없다.

따라서 해당 경우는 즉시 탐색을 종료한다.

```text
현재 칼로리 > 제한 칼로리
          ↓
    더 이상 탐색 X
```

예를 들어 제한 칼로리가 1000인데 현재까지 선택한 재료의 칼로리가 이미 1200이라면 이후 재료를 확인할 필요가 없다.

이러한 **가지치기(Pruning)**를 통해 불필요한 탐색을 줄일 수 있다.

### 4. 모든 재료를 확인하면 최댓값 갱신

`idx == N`이 되었다는 것은 모든 재료에 대해 선택 여부를 결정했다는 의미이다.

이때 칼로리 제한을 만족하는 조합이므로 현재 맛 점수와 기존 최대 맛 점수를 비교하여 더 큰 값을 저장한다.

결국 모든 가능한 조합 중

```text
칼로리 합 <= L
```

이라는 조건을 만족하면서

```text
맛 점수 합 = 최대
```

가 되는 경우를 찾게 된다.

# 시간복잡도

**O(2^N)**

각 재료마다

- 선택한다.
- 선택하지 않는다.

두 가지 경우가 존재한다.

따라서 N개의 재료에 대해 만들 수 있는 전체 부분집합의 개수는 최대 `2^N`개이므로 시간복잡도는 `O(2^N)`이다.

다만 칼로리가 제한 `L`을 초과하는 경우 즉시 탐색을 종료하는 가지치기를 적용하기 때문에 실제 탐색 횟수는 줄어들 수 있다.

<br>

# 배운 점

- N개의 원소 중 일부를 자유롭게 선택하는 문제는 **부분집합 DFS**로 접근할 수 있다.
- DFS에서 현재까지의 맛 점수와 칼로리처럼 **현재 상태를 매개변수로 전달**하면서 탐색할 수 있다.
- 제한 조건을 이미 만족할 수 없는 경우 즉시 `return`하는 **가지치기**를 사용하면 불필요한 탐색을 줄일 수 있다.
- 별도의 `visited` 배열 없이도 재귀 호출의 매개변수만으로 선택/미선택 상태를 표현할 수 있다.
- 최댓값을 구하는 완전탐색에서는 모든 선택이 끝나는 시점에 현재 결과와 정답을 비교하여 갱신하는 방식을 사용할 수 있다.

<br>

# 실수한 부분

- 재료를 반드시 하나 이상 선택해야 한다고 생각할 수 있지만, 핵심은 모든 재료에 대해 **선택하거나 선택하지 않는 경우를 모두 탐색**하는 것이다.
- 칼로리가 `L`과 같은 경우는 가능한 조합이다. 따라서 `sumCalorie >= L`이 아니라 **`sumCalorie > L`일 때만** 탐색을 종료해야 한다.
- DFS에서 현재 재료를 선택하는 경우만 탐색하면 일부 조합을 확인할 수 없으므로 반드시 **선택하지 않는 경우도 함께 탐색**해야 한다.
- 각 테스트케이스가 시작될 때 `maxScore`를 초기화하지 않으면 이전 테스트케이스의 결과가 남을 수 있으므로 주의해야 한다.
