# 접근 방법

각 재료마다 **포함하는 경우와 포함하지 않는 경우** 두 가지를 DFS로 탐색하는 완전탐색 문제로 접근했다.

재료의 개수 `N`이 최대 20개이므로 모든 부분집합을 확인하더라도 최대 `2^20`개의 경우의 수를 탐색한다. 따라서 완전탐색으로 해결할 수 있다고 판단했다.

DFS에서는 다음 세 가지 상태를 관리한다.

* `score` : 현재까지 선택한 재료의 맛 점수 합
* `idx` : 현재 선택 여부를 결정할 재료의 index
* `leftCalorie` : 현재 남아 있는 칼로리

현재 재료의 칼로리가 남은 칼로리 이하라면 해당 재료를 **선택하는 경우**를 탐색하고, 이와 별개로 해당 재료를 **선택하지 않는 경우**도 항상 탐색한다.

<br>

## 자료구조

* `int[][] ingredients`

    * 각 재료의 맛 점수와 칼로리를 저장한다.
    * `ingredients[i][0]` : 맛 점수
    * `ingredients[i][1]` : 칼로리

* `int answer`

    * 제한 칼로리를 넘지 않으면서 얻을 수 있는 최대 맛 점수를 저장한다.

처음에는 재료의 포함 여부를 저장하기 위해 `boolean[] isInclude`를 사용했지만, 최종적으로 어떤 재료를 선택했는지가 아니라 **최대 맛 점수만 구하면 되는 문제**이므로 별도의 방문/선택 배열이 필요하지 않았다.

<br>

# 핵심 아이디어

각 재료에서는 두 가지 선택지가 존재한다.

```text
                  idx번째 재료
                 /          \
              선택          미선택
               /               \
          idx + 1             idx + 1
```

### 1. 현재 재료를 선택

현재 재료를 추가해도 제한 칼로리를 넘지 않는다면 맛 점수를 더하고 남은 칼로리를 감소시킨다.

```java
if (calorie <= leftCalorie) {
    dfs(
        score + taste,
        idx + 1,
        leftCalorie - calorie
    );
}
```

### 2. 현재 재료를 선택하지 않음

현재 재료를 선택할 수 있는지와 관계없이 **선택하지 않는 경우도 반드시 탐색해야 한다.**

```java
dfs(score, idx + 1, leftCalorie);
```

현재 재료를 선택할 수 있다고 해서 반드시 선택하는 것이 최적의 결과를 만드는 것은 아니다.

현재 재료를 포기하고 남은 칼로리를 이후의 더 높은 맛 점수를 가진 재료에 사용하는 경우가 최적일 수도 있기 때문에 두 경우를 모두 확인해야 한다.

### 3. 모든 재료의 선택 여부를 결정했다면 최댓값 갱신

```java
if (idx == n) {
    answer = Math.max(answer, score);
    return;
}
```

`idx == n`이면 모든 재료에 대해 선택 여부를 결정한 것이므로 현재 맛 점수와 기존 최댓값을 비교한다.

<br>

# 시간복잡도

각 재료마다

* 선택한다.
* 선택하지 않는다.

두 가지 경우가 존재한다.

따라서 재료가 `N`개라면 최대 탐색 경우의 수는 `2^N`이므로 시간복잡도는 `O(2^N)`이다.

문제에서 `N <= 20`이므로 최악의 경우에도 `2^{20} = 1,048,576`개의 경우를 탐색한다.

따라서 DFS를 이용한 완전탐색으로 충분히 해결할 수 있다고 판단했다.

실제로는 칼로리 제한을 초과하는 선택 분기는 탐색하지 않으므로 모든 입력에서 정확히 `2^N`개의 경우를 끝까지 탐색하는 것은 아니다.

<br>

# 배운 점

* 부분집합을 DFS로 탐색할 때는 각 원소마다 **선택 / 미선택 두 가지 경우를 모두 탐색해야 한다.**
* 백트래킹에서 상태를 원래 값으로 복구하는 것과 새로운 경우의 수를 탐색하는 것은 서로 다른 동작이다.
* `boolean` 값을 `false`로 원복했다고 해서 **미선택 상태의 DFS가 자동으로 실행되는 것은 아니다.**
* 현재 선택 결과 자체가 필요하지 않고 누적 값만 필요하다면 `boolean[]`과 같은 별도의 선택 상태 배열 없이 DFS의 매개변수만으로도 해결할 수 있다. 
* 입력 크기를 보고 `2^N`을 직접 계산해보면 완전탐색 가능 여부를 빠르게 판단할 수 있다.

<br>

# 실수한 부분

처음에는 boolean[] isInclude를 사용해 현재 재료의 포함 여부를 관리했다.

```
if (calorie <= leftCalorie) {
isInclude[idx] = true;
dfs(score + taste, idx + 1, leftCalorie - calorie);
isInclude[idx] = false;
}
```

true로 변경한 뒤 DFS를 실행하고 다시 false로 원복했기 때문에 선택하지 않은 경우도 처리했다고 생각했다.

하지만 `isInclude[idx] = false;` 는 단순히 현재 상태를 원래 상태로 복구하는 백트래킹 과정일 뿐이다.

false인 상태에서 다음 DFS를 호출하지 않았기 때문에 실제 탐색 트리에는 현재 재료를 선택하지 않는 경우가 존재하지 않았다.

즉, `isInclude[idx] = false;`와 `dfs(score, idx + 1, leftCalorie);`는 완전히 다른 역할을 한다.

처음 구현은 사실상 다음과 같은 구조였다.

```
재료를 선택할 수 있음
↓
선택
↓
DFS
↓
false로 상태 복구
↓
종료
```


하지만 필요한 탐색은 다음과 같다.
```
              현재 재료
              /      \
           선택      미선택
            ↓           ↓
           DFS         DFS
```

따라서 현재 재료를 선택하는 DFS와 별개로 다음 호출을 추가해야 했다.

`dfs(score, idx + 1, leftCalorie);`

최종적으로는 선택 여부 자체를 저장할 필요가 없다는 것을 확인하고 boolean[] isInclude를 제거했다.
