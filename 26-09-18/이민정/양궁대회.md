# 접근 방법

라이언이 `n`개의 화살을 10점부터 0점까지 어떻게 분배할지 모두 탐색하는 **DFS 완전탐색**으로 접근했다.

각 점수에 사용할 화살의 개수를 `0 ~ remainRound` 범위에서 선택하고, 선택한 화살 수만큼 남은 화살을 감소시키면서 다음 점수로 이동한다.

모든 화살을 사용했거나 0점까지 탐색한 경우 현재 화살 배치에 대해 어피치와 라이언의 점수를 계산한다.

이후 다음 조건에 따라 정답을 갱신한다.

1. 라이언과 어피치의 점수 차이가 현재 최대 점수 차이보다 크다면 정답을 갱신한다.
2. 최대 점수 차이가 같다면 **더 낮은 점수를 많이 맞힌 경우**를 정답으로 선택한다.
3. 이를 위해 배열의 뒤쪽인 `0점(index 10)`부터 역순으로 비교하고 처음으로 화살 개수가 달라지는 위치를 기준으로 판단한다.

<br>

## 자료구조

* `int[] lionScore`

    * 현재 DFS에서 탐색 중인 라이언의 화살 배치를 저장한다.
    * `index 0`은 10점, `index 10`은 0점을 의미한다.

* `int[] apeachScore`

    * 어피치의 화살 배치를 저장한다.

* `int[] result`

    * 현재까지 발견한 최적의 라이언 화살 배치를 저장한다.

* `int maxDiff`

    * 현재까지의 라이언과 어피치의 최대 점수 차이를 저장한다.

<br>

# 핵심 아이디어

### 1. 화살 배치를 DFS로 완전탐색

각 점수에서 사용할 수 있는 화살 수를 모두 선택한다.

```java
for (int i = 0; i <= remainRound; i++) {
    lionScore[idx] = i;
    dfs(remainRound - i, idx - 1);
}
```

`i < remainRound`가 아니라 `i <= remainRound`여야 한다.

현재 점수에 **남은 화살을 전부 사용하는 경우** 역시 가능한 경우의 수이기 때문이다.


### 2. 점수 계산

각 점수에서 라이언이 어피치보다 더 많은 화살을 맞혔다면 라이언이 점수를 얻고, 그렇지 않으면 어피치가 점수를 얻는다.

단, 두 사람 모두 화살을 맞히지 않은 점수는 누구도 가져가지 않는다.

```java
if (apeachScore[i] != 0 && apeachScore[i] >= lionScore[i]) {
    apeach += (10 - i);
} else if (lionScore[i] != 0) {
    lion += (10 - i);
}
```

### 3. 점수 차이가 같다면 낮은 점수부터 비교

문제에서는 점수 차이가 동일한 경우 **더 낮은 점수를 많이 맞힌 경우**를 정답으로 선택해야 한다.

따라서 배열의 마지막인 `0점`부터 역순으로 비교한다.

```java
for (int i = lionScore.length - 1; i >= 0; i--) {
    if (lionScore[i] > result[i]) {
        result = Arrays.copyOf(lionScore, lionScore.length);
        break;
    }

    if (lionScore[i] < result[i]) {
        break;
    }
}
```

여기서 처음으로 다른 값이 나온 순간 결과가 결정된다.

`lionScore[i] > result[i]`라면 새로운 배열이 더 좋은 답이고,

반대로 `lionScore[i] < result[i]` 라면 기존 `result`가 더 좋은 답이므로 **즉시 비교를 종료해야 한다.**

뒤의 더 높은 점수 구간까지 계속 비교하면 문제에서 요구하는 우선순위와 다른 결과를 선택할 수 있다.

<br>

# 시간복잡도

화살 `n`개를 11개의 점수 구간에 분배하는 경우의 수는 중복조합으로 생각할 수 있다.

$$
\binom{n + 10}{10}
$$

각 화살 배치마다 점수를 계산하는 데 최대 11개의 점수를 확인하고, 동점인 경우에도 최대 11개의 원소를 비교한다.

따라서 시간복잡도는 대략 다음과 같다.

$$
O\left(11 \times \binom{n+10}{10}\right)
$$


문제에서 `n <= 10`이므로 최악의 경우에도 다음의 화살 배치만 확인하면 되기 때문에 완전탐색이 가능하다고 판단했다.

$$
\binom{20}{10} = 184756
$$

# 배운 점

* DFS를 사용할 때 현재 상태에서 가능한 범위를 정확하게 포함해야 한다.

    * `i < remainRound`와 `i <= remainRound`의 차이처럼 경계 조건 하나 때문에 특정 경우의 수가 통째로 누락될 수 있다.

* 배열의 우선순위를 비교할 때는 **처음으로 값이 달라지는 위치에서 결과가 결정되는지** 확인해야 한다.

* 이 문제의 동점 조건은 낮은 점수부터 비교하는 비교로 생각할 수 있다.

* 입력 크기가 작다면 무조건 복잡한 최적화를 적용하기보다 가능한 경우의 수를 먼저 계산하고 완전탐색이 가능한지 판단하는 것도 중요하다.

# 실수한 부분
1. DFS 탐색 범위에서 등호를 누락

처음에는 다음과 같이 작성했다.

`for (int i = 0; i < remainRound; i++)`

이 경우 현재 점수에 남은 화살을 전부 사용하는 `i == remainRound` 경우가 탐색되지 않는다.

따라서 다음과 같이 수정했다.

`for (int i = 0; i <= remainRound; i++)`

2. 동점 비교에서 반대 경우의 종료 조건을 누락

처음에는 다음 조건만 확인했다.

```
if (lionScore[i] > result[i]) {
result = Arrays.copyOf(lionScore, lionScore.length);
break;
}
```

하지만 낮은 점수부터 비교하다가 `lionScore[i] < result[i]` 가 나온 순간 기존 result가 더 좋은 답이라는 것이 이미 결정된다.

따라서 다음 조건 역시 필요하다.

```
if (lionScore[i] < result[i]) {
break;
}
```

3. DFS 배열 상태 관리 주의

현재 구현처럼 lionScore 배열 하나를 모든 DFS 호출에서 공유한다면 이전 탐색의 값이 남지 않도록 주의해야 한다.

특히 `if (remainRound == 0 || idx == 0)` 처럼 remainRound == 0인 순간 탐색을 조기 종료하면 아직 방문하지 않은 낮은 index 영역에 이전 DFS의 값이 남아 있을 수 있다.

따라서 백트래킹 후 값을 초기화하거나, 남은 화살이 0이더라도 나머지 index를 0으로 확정하면서 끝까지 내려가는 방식으로 상태를 명확하게 관리하는 것이 안전하다.

예를 들어 다음과 같이 백트래킹할 수 있다.

```
for (int i = 0; i <= remainRound; i++) {
lionScore[idx] = i;
dfs(remainRound - i, idx - 1);
lionScore[idx] = 0;
}
```

DFS에서 하나의 배열을 공유할 때는 현재 호출에서 변경한 상태를 재귀 호출 이후 원래 상태로 복구하는 것을 항상 확인해야 한다.
