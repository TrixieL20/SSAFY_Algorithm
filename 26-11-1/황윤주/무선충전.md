# 접근 방법

- 사용자 A와 B가 주어진 이동 경로에 따라 움직이면서 얻을 수 있는 총 충전량의 최댓값을 구하는 문제이다.
- 처음에는 BFS를 이용해 사용자의 이동을 처리하려고 했지만, 이동 방향이 이미 정해져 있으므로 **시뮬레이션**으로 해결할 수 있다.
- 각 BC의 위치, 충전 범위, 충전 성능을 `AP` 클래스로 저장한다.
- 매 시간 사용자 A와 B를 이동시키고, 각각 충전 가능한 BC를 확인한다.
- 두 사용자가 선택할 수 있는 모든 BC 조합을 비교하여 현재 시간의 최대 충전량을 계산한다.
- 같은 BC를 동시에 사용하면 충전 성능을 나눠 가지므로 두 사람의 충전량 합계는 해당 BC의 성능과 같다.
- 매 시간 계산한 최대 충전량을 `answer`에 누적한다.

## 자료구조

- `AP[] aps` : 각 BC의 정보를 객체 배열로 저장
- `AP` : BC의 행(`r`), 열(`c`), 충전 범위(`charge`), 충전 성능(`p`) 저장
- `int[] userA`, `int[] userB` : 사용자 A와 B의 이동 방향 저장
- `int[] dr`, `int[] dc` : 상하좌우 및 정지 이동을 위한 방향 배열
- `int answer` : 두 사용자의 총 충전량
- `int M, A` : 총 이동 시간과 BC 개수

<br>

# 핵심 아이디어

- 이동 경로가 정해져 있으므로 BFS 없이 반복문으로 사용자 위치를 갱신한다.
- **0초에도 충전할 수 있으므로 이동하기 전에 먼저 충전량을 계산한다.**
- 충전 가능 여부는 맨해튼 거리로 판단한다.
- `|사용자 행 - BC 행| + |사용자 열 - BC 열| <= 충전 범위`이면 충전할 수 있다.
- 충전 범위가 겹칠 수 있으므로 `map`에 BC 하나만 저장하기보다 `AP[]`을 순회하며 충전 가능 여부를 확인한다.
- 사용자 A와 B가 선택할 BC 조합을 이중 반복문으로 모두 확인한다.
- 같은 BC를 선택하고 두 사용자 모두 충전 가능한 경우에는 해당 BC의 성능만 한 번 더한다.
- 서로 다른 BC를 선택한 경우에는 각 BC의 충전 성능을 더한다.
- 현재 시간의 최대 충전량을 구한 뒤 전체 충전량에 누적한다.

### 시뮬레이션 진행 과정

1. 사용자 A는 `(0,0)`, B는 `(9,9)`에서 시작한다.
2. 이동 전인 0초의 최대 충전량을 계산한다.
3. 각 사용자의 이동 방향에 따라 위치를 갱신한다.
4. 현재 위치에서 충전 가능한 BC를 확인한다.
5. 모든 BC 선택 조합을 비교하여 최대 충전량을 구한다.
6. 최대 충전량을 `answer`에 누적한다.
7. 총 M번 이동할 때까지 반복한다.

<br>

# 시간복잡도

**O((M + 1) × A²)**

- `M`은 총 이동 시간, `A`는 BC의 개수이다.
- 0초부터 M초까지 총 `M + 1`번 충전량을 계산한다.
- 각 시간마다 사용자 A와 B의 BC 선택 조합을 이중 반복문으로 확인한다.
- BC를 선택하지 않는 경우까지 포함하면 `(A + 1)²`개의 조합을 검사한다.
- 각 조합의 충전 가능 여부는 맨해튼 거리로 상수 시간에 계산할 수 있다.
- 따라서 전체 시간복잡도는 `O((M + 1) × A²)`이다.

**공간복잡도: O(M + A)**

- 사용자 A와 B의 이동 정보를 저장하는 배열이 필요하다.
- BC 정보를 저장하는 `AP[]` 배열이 필요하다.
- 사용자 위치는 별도 배열 없이 변수로 관리한다.

<br>

# 배운 점

- 이동 경로가 이미 주어진 문제는 BFS보다 시뮬레이션이 적합할 수 있다.
- 여러 속성을 가진 데이터를 저장할 때는 클래스를 정의하고 객체 배열로 관리할 수 있다.
- `AP[] aps = new AP[A]`로 객체 배열을 생성하고 `new AP(...)`로 각 객체를 저장한다.
- 맨해튼 거리를 이용하면 격자에서 두 위치 사이의 이동 거리로 충전 범위를 판단할 수 있다.
- 충전 범위가 겹치는 경우에는 하나의 위치에서 여러 BC를 이용할 수 있다는 점을 고려해야 한다.
- 두 사용자가 각각 선택할 수 있는 BC의 모든 조합을 비교하면 최대 충전량을 구할 수 있다.
- 매 순간 최대 충전량을 계산하여 누적하는 방식으로 전체 결과를 구할 수 있다.

# 실수한 부분

### 1. BFS로 접근하려고 함

처음에는 `Queue`를 이용해 A와 B의 위치를 관리하려고 했다.

하지만 사용자 이동 경로가 이미 입력으로 주어지므로 BFS 탐색이 필요하지 않다.

반복문으로 현재 위치를 갱신하는 시뮬레이션 방식으로 변경했다.



### 2. BC 좌표를 반대로 저장함

BC 입력은 `X Y C P` 순서이지만, AP 클래스에서는 `r, c` 순서로 저장한다.

따라서 X는 열, Y는 행으로 변환해야 한다.

```java
aps[i] = new AP(y - 1, x - 1, charge, p);
```

문제 좌표는 1부터 시작하고 배열 인덱스는 0부터 시작하므로 각각 1을 빼준다.




### 3. 0초 충전을 고려하지 않음

사용자는 이동하기 전 시작 위치에서도 충전할 수 있다.

따라서 이동 반복문을 시작하기 전에 충전량을 계산해야 한다.

```java
answer += getMaxCharge(rA, cA, rB, cB);
```
