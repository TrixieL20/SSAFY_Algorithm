# 문제 정보

| 항목 | 내용 |
|---|---|
| 문제 이름 | 구명보트 |
| 난이도 | Lv2 |
| 플랫폼 | 프로그래머스 |
| 사용 알고리즘 | 그리디, 투 포인터 |

<br>

# 접근 방법

- 먼저 사람들의 몸무게를 오름차순으로 정렬한다.
- 가장 가벼운 사람과 가장 무거운 사람을 선택하는 **투 포인터** 방식을 사용한다.
- 두 사람의 몸무게 합이 `limit` 이하라면 함께 탑승시킨다.
- 무게 제한을 초과한다면 가장 무거운 사람은 혼자 탑승해야 한다.
- 이 과정을 반복하면서 필요한 구명보트의 개수를 계산한다.

## 자료구조

- `int[] people` : 사람들의 몸무게를 저장하는 배열
- `int front` : 가장 가벼운 사람을 가리키는 포인터
- `int rear` : 가장 무거운 사람을 가리키는 포인터
- `int ans` : 필요한 구명보트의 개수
- `boolean[] visited` : 처음 풀이에서 탑승 여부를 확인하기 위해 사용한 배열

<br>

# 핵심 아이디어

- 가장 무거운 사람부터 처리하는 것이 핵심이다.
- 가장 무거운 사람과 가장 가벼운 사람도 함께 탈 수 없다면, 가장 무거운 사람은 다른 누구와도 함께 탈 수 없다.
- 따라서 두 사람의 합이 `limit`을 초과하면 `rear--`만 수행한다.
- 두 사람의 합이 `limit` 이하라면 함께 탑승시키고 `front++`, `rear--`를 수행한다.
- 한 번의 반복마다 구명보트 한 대를 사용하므로 `ans++`한다.
- 두 포인터가 같은 위치에 도달했다면 마지막 한 명도 구명보트에 탑승해야 한다.

### 투 포인터 진행 과정

1. `Arrays.sort(people)`로 몸무게 오름차순 정렬
2. `front = 0`, `rear = people.length - 1`로 초기화
3. 가장 가벼운 사람과 무거운 사람의 몸무게 합 계산
4. 합이 `limit` 이하라면 두 사람을 함께 탑승시키고 양쪽 포인터 이동
5. 합이 `limit`을 초과하면 무거운 사람만 탑승시키고 `rear--`
6. 구명보트 개수 증가
7. `front <= rear`인 동안 반복

<br>

# 시간복잡도

**O(N log N)**

- `N`은 사람의 수이다.
- `Arrays.sort()`를 이용한 정렬에 `O(N log N)`이 필요하다.
- 투 포인터 탐색은 각 사람을 한 번씩 처리하므로 `O(N)`이다.
- 따라서 전체 시간복잡도는 `O(N log N)`이다.

**추가 공간복잡도: O(log N)**

- 개선된 풀이에서는 별도의 방문 배열을 사용하지 않는다.
- Java의 기본형 배열 정렬 과정에서 재귀 호출 스택이 사용될 수 있다.
- 처음 작성한 `visited` 배열 방식은 추가로 `O(N)`의 공간이 필요하다.

<br>

# 배운 점

- 투 포인터는 정렬된 배열에서 양쪽 끝의 값을 비교할 때 활용할 수 있다.
- 구명보트 문제는 매 순간 가장 무거운 사람을 어떻게 태울지 결정하는 그리디 알고리즘이다.
- 두 사람의 합이 제한을 초과하면 무거운 사람만 처리하고, 제한 이하라면 두 사람을 함께 처리한다.
- 포인터를 이동시키는 것만으로 탑승 여부를 관리할 수 있으므로 `visited` 배열이 필요하지 않다.
- 투 포인터의 종료 조건은 남은 원소를 어떻게 처리하는지에 따라 달라진다.

<br>

# 실수한 부분

### 1. visited 배열을 불필요하게 사용함

처음에는 두 사람이 함께 탑승한 경우 방문 처리하고, 마지막에 방문하지 않은 사람들을 한 명씩 탑승시키는 방식으로 구현했다.

```java
visited[front] = true;
visited[rear] = true;
```

하지만 포인터가 이동하면 해당 사람은 이미 처리된 것이므로 별도의 방문 배열이 필요하지 않다.

### 2. 구명보트 개수를 증가시키는 위치

처음에는 두 사람이 함께 탑승하는 경우에만 `ans++`하고, 나머지 사람들은 별도로 계산했다.

하지만 무거운 사람이 혼자 타는 경우에도 구명보트 한 대가 필요하다.

따라서 조건문 밖에서 매 반복마다 `ans++`하면 더 간단하게 구현할 수 있다.

### 3. 투 포인터 종료 조건

처음에는 다음과 같이 작성했다.

```java
while (front < rear)
```

이 경우 포인터가 같은 위치에 도달했을 때 마지막 한 명이 처리되지 않으므로 별도 처리가 필요하다.

```java
while (front <= rear)
```

이렇게 작성하면 마지막 한 명까지 반복문 안에서 처리할 수 있다.

### 4. 무게 제한을 초과하는 경우

두 사람의 합이 `limit`을 초과하면 가벼운 사람을 제외하는 것이 아니라 **무거운 사람을 혼자 태워야 한다.**

가장 가벼운 사람과도 함께 탈 수 없기 때문에 다른 사람과도 함께 탈 수 없기 때문이다.
