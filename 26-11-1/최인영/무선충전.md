# 문제 정보

| 항목 | 내용 |
| ----- | ----- |
| 문제 이름 | 5644. 무선 충전 |
| 난이도 | 모의 SW 역량테스트 |
| 플랫폼 | SWEA |

# 접근 방법
- **시뮬레이션 + 완전탐색**
- 매초 A, B의 위치를 갱신하고, 각각 충전 가능한 BC를 탐색
- A, B가 선택할 수 있는 **모든 BC 조합**을 확인해 해당 시간의 최대 충전량 계산
- 0초부터 M초까지 각 시간의 최대 충전량을 누적

## 자료구조
- `List<int[]> chargers`: BC 정보 저장 (`X`, `Y`, 충전 범위 `C`, 성능 `P`)
- `boolean[] aChargable, bChargable`: 각 BC에 대한 A, B의 충전 가능 여부 저장
- `int[] aRoute, bRoute`: A, B의 시간별 이동 방향 저장

# 핵심 아이디어

* 🌟 **매초 A, B가 충전 가능한 BC 조합을 모두 고려**
  - 맨해튼 거리 `|X1-X2| + |Y1-Y2|`가 BC의 충전 범위 이하라면 충전 가능
  - `boolean[]`을 통해 각 BC에 접근할 수 있는지 확인
  - 이중 반복문으로 A, B가 선택하는 모든 BC 조합 탐색

* 🌟 **BC 중복 사용 여부에 따라 충전량 계산**
  - A, B 모두 같은 BC에서 충전 가능 → BC 성능을 공유하므로 총 충전량은 해당 BC의 성능
  - 서로 다른 BC에서 충전 → 각각의 충전량을 합산
  - 둘 중 한 명만 충전 가능 → 충전 가능한 사람의 충전량만 반영
  - 둘 다 충전 불가능 → 충전량 0

* 🌟 **매초 최대 충전량을 구해 누적**
  - 모든 BC 조합의 충전량을 비교해 `max` 갱신
  - `maxCharge += max`
  - 현재 선택한 BC가 다음 시간의 이동이나 충전에 영향을 미치지 않으므로 매초 독립적으로 최댓값 계산 가능

* 🌟 **0초 충전 고려**
  - 이동하기 전 초기 위치에서도 충전할 수 있으므로 `charge()` 먼저 호출
  - 이후 M번 이동하면서 매번 `charge()` 호출
  - 총 M+1번의 충전 수행

# 시간복잡도

**O(M × A²)**

- M: 총 이동 시간
- A: BC 개수
- 매초 충전 가능 여부 확인: `O(A)`
- 매초 모든 BC 조합 탐색: `O(A²)`
- 총 M+1번 충전하므로 `O((M+1) × A²)`

**공간복잡도: O(M + A)**

- 이동 경로 배열: `O(M)`
- 충전기 정보 및 충전 가능 여부 배열: `O(A)`

# 배운 점
- 시뮬레이션 문제에서는 **초기 상태(0초)도 처리해야 하는지** 확인해야 함
- 두 사람이 동일한 자원을 공유하는 경우, 각각의 최댓값을 구하는 것이 아니라 **조합별 합계의 최댓값**을 구해야 함
- `boolean[]`을 활용하면 각 BC의 충전 가능 여부를 실제 BC 인덱스와 연결해 간단하게 관리할 수 있음
- 완전탐색 시 모든 예외 상황을 고려해야 하며, 특히 **선택할 수 있는 대상이 없는 경우**도 확인해야 함

# 실수한 부분
- **A, B 중 한 명만 충전 가능한 경우 누락**
  - 처음에는 두 사람의 충전 가능한 BC 리스트를 이중 반복문으로 탐색
  - 한 명의 리스트가 비어 있으면 반복문이 실행되지 않아 다른 사람도 충전하지 못하는 것으로 계산
  - `boolean[]`로 변경하고, 각 사람의 충전 가능 여부에 따라 충전량을 개별적으로 더하도록 수정

- **리스트 인덱스와 실제 BC 인덱스를 혼동**
  - 처음에는 `aChargers`, `bChargers`의 인덱스 `i == j`로 동일 BC 여부 판단
  - 각 리스트의 같은 인덱스가 같은 BC를 의미하지 않음
  - 실제 BC 인덱스를 기준으로 관리하는 `boolean[]` 방식으로 수정

- **A, B의 최대 충전량을 각각 구해 합산**
  - 각자 최대 충전량을 얻는 조합이 서로 다를 수 있어 실제로 불가능한 충전량이 계산됨
  - 각 BC 조합의 충전량을 먼저 합산한 뒤 최댓값을 갱신하도록 수정

- **동일 BC 선택 조건 처리 오류**
  - 처음에는 `i == j`만으로 동일 BC의 성능을 반영해 충전 불가능한 경우에도 충전량이 더해짐
  - 이후 `||` 조건으로 서로 다른 BC에서 충전하는 경우까지 동일 BC로 처리하는 오류 발생
  - 최종적으로 `i == j && aChargable[i] && bChargable[j]`일 때만 공유 충전으로 처리하고, 나머지는 각자의 충전 가능 여부에 따라 계산

- **이동 방향 및 입력 처리**
  - X는 가로, Y는 세로 좌표인데 처음에는 이동 방향 배열을 반대로 설정
  - 이동 정보는 M개인데 처음에는 M+1개를 입력받으려고 함
  - 이동 방향 수정 및 0초 충전과 M번 이동을 분리해 해결

## 반영 내용
- 충전 가능한 BC를 `List<Integer>` 대신 `boolean[]`로 관리
- A, B의 모든 BC 조합을 탐색하면서 충전 가능 여부 및 동일 BC 공유 조건 처리
- 한 명만 충전 가능한 경우와 둘 다 충전 불가능한 경우까지 고려
- 0초 충전 및 좌표 이동 방향 수정
