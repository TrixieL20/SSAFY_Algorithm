# 문제 정보

| 항목    | 내용     |
| ----- | ------ |
| 문제 이름 | 구명보트   |
| 난이도   | Lv.2   |
| 플랫폼   | 프로그래머스 |

## 접근 방법

- 사람들의 몸무게를 오름차순으로 정렬한다.
- 투 포인터를 활용하여 가장 가벼운 사람(`left`)과 가장 무거운 사람(`right`)을 선택한다.
- 두 사람의 몸무게 합이 제한 무게 이하라면 함께 탑승시키고 양쪽 포인터를 이동한다.
- 제한 무게를 초과한다면 가장 무거운 사람만 탑승시키고 `right` 포인터를 이동한다.
- 마지막에 한 명이 남았다면 구명보트 한 대를 추가한다.
- 모든 사람을 구출할 때까지 반복하여 필요한 구명보트의 최소 개수를 구한다.

## 핵심 아이디어

- 그리디 알고리즘 + 투 포인터를 활용한다.
- 가장 무거운 사람부터 처리하면 구명보트의 개수를 최소화할 수 있다.
- 가장 무거운 사람과 가장 가벼운 사람도 함께 탈 수 없다면, 가장 무거운 사람은 다른 누구와도 함께 탈 수 없으므로 혼자 탑승해야 한다.
- 두 사람이 함께 탈 수 있다면 가장 가벼운 사람을 짝지어 태우는 것이 유리하다.
- 정렬 후 양 끝에서 탐색하므로 불필요한 조합 탐색을 줄일 수 있다.

## 시간복잡도

- 시간복잡도: O(N log N)
  - 정렬: O(N log N)
  - 투 포인터 탐색: O(N)
- 공간복잡도: O(log N)
  - 투 포인터에 필요한 추가 공간: O(1)
  - Java의 `Arrays.sort(int[])` 정렬 과정에서 사용하는 스택 공간: O(log N)
