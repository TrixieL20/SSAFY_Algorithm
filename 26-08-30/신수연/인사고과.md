# 접근 방법

각 직원의 근무 태도 점수와 동료 평가 점수를 기준으로 **인센티브 대상 여부를 먼저 판단한 후**, 완호보다 총점이 높은 직원의 수를 세어 순위를 계산한다.

두 점수가 모두 다른 직원보다 낮다면 인센티브를 받을 수 없기 때문에, 모든 직원을 직접 비교하면 `O(n²)`의 시간이 필요하다.

이를 개선하기 위해 직원을 **근무 태도 점수 내림차순**으로 정렬하고, 근무 태도 점수가 같은 경우에는 **동료 평가 점수 오름차순**으로 정렬한다.

이렇게 정렬하면 현재 직원보다 근무 태도 점수가 높은 직원들을 먼저 확인할 수 있다. 따라서 앞에서 확인한 직원들의 동료 평가 점수 중 최댓값을 관리하면서 현재 직원의 동료 평가 점수가 그보다 낮은지만 확인하면 인센티브 대상 여부를 판단할 수 있다.

<br>

# 핵심 아이디어

### 1. 근무 태도 점수 기준으로 정렬

근무 태도 점수가 높은 직원부터 확인할 수 있도록 내림차순으로 정렬한다.

근무 태도 점수가 같은 경우에는 동료 평가 점수를 오름차순으로 정렬한다.

```java
Arrays.sort(scores, (a, b) -> {
    if (a[0] == b[0]) {
        return Integer.compare(a[1], b[1]);
    }
    return Integer.compare(b[0], a[0]);
});
```

이렇게 정렬하면 현재 직원보다 근무 태도 점수가 높은 직원들은 이미 앞에서 확인한 상태가 된다.

### 2. 동료 평가 점수의 최댓값 관리

앞에서 확인한 직원들의 동료 평가 점수 중 최댓값을 `maxPeer`에 저장한다.

현재 직원의 동료 평가 점수가 `maxPeer`보다 작다면, 현재 직원은 자신보다 근무 태도 점수가 높으면서 동료 평가 점수도 높은 직원이 존재한다는 의미이다.

따라서 두 평가 점수 모두 다른 직원보다 낮아져 **인센티브 대상에서 제외**된다.

```java
if (score[1] < maxPeer) {
    ...
    continue;
}
```

반대로 인센티브 대상이라면 현재 직원의 동료 평가 점수를 기준으로 `maxPeer`를 갱신한다.

```java
maxPeer = Math.max(maxPeer, score[1]);
```

### 3. 완호가 인센티브 대상에서 제외되는 경우

완호의 점수와 현재 직원의 점수가 같은 경우, 현재 직원이 완호라는 의미이다.

완호가 인센티브 대상에서 제외된다면 바로 `-1`을 반환한다.

```java
if (score[0] == attitude && score[1] == peer) {
    return -1;
}
```

### 4. 완호의 순위 계산

인센티브 대상인 직원 중에서 완호보다 총점이 높은 직원의 수를 센다.

완호의 총점은 미리 계산해두고,

```java
int total = attitude + peer;
```

현재 직원의 총점이 완호보다 높다면 `rank`를 증가시킨다.

```java
if (score[0] + score[1] > total) {
    rank++;
}
```

최종적으로 `rank`를 반환하면 완호의 인센티브 순위를 구할 수 있다.

<br>

# 시간복잡도

직원들을 한 번 정렬하는 데 `O(n log n)`이 필요하다.

정렬 이후에는 모든 직원을 한 번 순회하면서 `maxPeer`를 확인하고 순위를 계산하므로 `O(n)`이 걸린다.

따라서 전체 시간복잡도는 **O(n log n)**이다.

정렬에 필요한 배열 외에 `maxPeer`, `rank` 등의 변수만 사용하므로 추가 공간복잡도는 **O(1)**이다.
단, `Arrays.sort()`의 내부 정렬 과정에서 사용하는 공간은 별도로 고려할 수 있다.

# 어려웠던 점

이 문제에서 가장 어려웠던 부분은 **두 점수가 모두 낮은 직원을 효율적으로 제외하는 방법**을 찾는 것이었다.

모든 직원을 서로 비교하면 `O(n²)`이 되기 때문에, 근무 태도 점수를 기준으로 정렬한 뒤 앞에서 확인한 직원들의 **동료 평가 점수 최댓값을 관리하는 방식**으로 개선했다.

특히 근무 태도 점수가 같은 직원들은 동료 평가 점수를 오름차순으로 정렬해야 한다. 이렇게 해야 같은 근무 태도 점수를 가진 직원끼리 비교할 때 현재 직원보다 동료 평가 점수가 높은 직원이 먼저 처리되는 것을 방지할 수 있다.

결과적으로 **정렬 순서를 적절하게 설정하고, 앞에서 확인한 동료 평가 점수의 최댓값만 관리하는 것**이 이 문제의 핵심이었다.
