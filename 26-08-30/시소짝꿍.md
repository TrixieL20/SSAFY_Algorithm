# 접근 방법 / 핵심 아이디어

문제를 보니 완점탐색은 시간초과 나겠다. 라고 생각을 했습니다.
배열의 최대크기는 10만이지만 무게의 범위는 100 < w < 1000 이라서, 중복을 제거하면 길이가 900정도 되겟구나 파악했고
그래서 주어진 배열을 집합에 넣었다 뺴서 중복을 제거하여서 리스트 길이를 줄였습니다

이후에는 Map<Integer,Integer>타입으로 몸무게당 개수를 저장하였고, 중복되는 몸무게는 nC2로 , 다른 몸무게는 반복문과 조건문으로 균형이 맞는 쌍을 카운트했습니다.



<br>

# 시간복잡도

O(N + D²)   (D ≤ 901, 사실상 상수)

O(N) : numbcerCounter, set 채우기 -> weights 순회
O(D^2) : 중복x 몸무게 개수리스트 이중 for문

<br>

# 어려웠던 점 / 배운점

이번 문제는 테스트케이스가 적어서 애를 먹었다. 
문제도 정확히 읽지않아서 중심으로부터 거리가 1m도 있는줄알고
최소공배수를 구해서 둘 중 작은 값이 최소공배수에 도달할 수 있나로 균형을 판단했는데 실수였다.

또 중복의 수를 nC2를 구할때 만약 n이 10만이라면 int에서는 오버플로우가 났는데 알아차리지 못해서 시간을 버렸었다
출력의 타입범위도 잘 체크해야겠다..
