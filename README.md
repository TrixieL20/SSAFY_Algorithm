# 📌 Study Rules

## 1. Language

* **Java만 사용합니다.**
* 일반적인 코딩테스트와 같이 Java 8을 기준으로 코드를 작성합니다.

<br>

## 2. Weekly Mission

* 매주 **2개의 문제**를 풉니다.
* 아주 특별한 사유가 아니라면 스터디 일정은 미루지 않습니다.
* **매주 일요일 23:59까지** PR을 생성하여 제출합니다.

<br>

## 3. Code Review

다음 주 **화요일 스터디 전까지**

* 상대방의 코드를 미리 읽어옵니다.
* 코드의 개선사항은 **PR Review**를 활용합니다.
* 상대방에게 어떤 점을 간략히 말하면 좋을지 고민해봅니다.


### 화요일 스터디 이야기 주제

* 문제당 약 **1~2분**
* 접근 방식
* 구현 포인트
* 어려웠던 점
* 공유하고 싶은 내용

접근 방식에 대한 질문이나 제안은 PR Review나 화요일 발표 시간에 합니다.

<br>

## 4. PR 규칙

모든 제출은 **PR(Pull Request)** 로 진행합니다.

### Branch Name

```
YY/MM/DD_본인이니셜(대문자)
```

예시

```
26/08/02_HGD
```


### PR 제목
```
YY/MM/DD 본인이름 문제 풀이
```

<br>

## 5. 폴더 구조

주차 폴더는 **해당 주 일요일 날짜**로 생성합니다.

해당 주차의 폴더에 **자신의 이름**으로 폴더를 만들고 해당 폴더에 자신의 코드와 README 파일들을 올립니다.

예시

```
26-08-02
26-08-09
26-08-16
```

<br>

## 6. 파일명 규칙

### 문제 번호가 없는 경우

```
문제명.java
```

예시

```
게임맵최단거리.java
```

<br>

### 문제 번호가 있는 경우

```
번호_문제명.java
```

예시

```
26837_DNA수열.java
```

<b>파일명에는 띄어쓰기를 사용하지 않습니다.</b>

<br>

## 7. 풀이 문서

각 문제마다 풀이를 함께 작성합니다.

Java 파일과 동일한 이름으로 확장자만 `.md`를 사용합니다.

예시

```
26837_DNA수열_홍길동.md
게임맵최단거리_홍길동.md
```

<br>
내용에는 다음과 같은 내용을 간단히 작성합니다.

* 문제 접근 방식
* 핵심 아이디어
* 시간복잡도
* 풀이하면서 실수했던 부분
* 다시 푼다면 개선하고 싶은 점

<br>

## 8. 코드 수정

화요일 스터디 이후

* 받은 리뷰를 반영합니다.
* 개선사항은 동일한 PR에 추가 커밋으로 수정합니다.

* 제출은 반드시 PR로 진행

* 개선 의견은 이유와 함께 제안합니다.

함께 성장하는 것을 가장 중요한 목표로 합니다.
