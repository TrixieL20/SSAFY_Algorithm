## 1️⃣ 문제 접근 방식

#### 📌 사용 알고리즘 - 그리디

매 라운드마다 카드 2장을 새로 받고, 가지고 있는 카드들 중 합이 `n+1`이 되는 두 장이 되는 케이스를 최대한 동전 소모가 적은 것 우선으로 찾도록 구현했음 !

## 2️⃣ 핵심 아이디어

🌟 처음 받은 n/3장의 카드는 my_deck, 이후 새로 받는 카드는 new_deck에 따로 저장

🌟 합이 n+1이 되는 카드 조합을 동전 소모가 적은 순서대로 탐색

* 기존 카드 + 기존 카드 ➡️ 코인 0개
* 기존 카드 + 새 카드 ➡️ 코인 1개
* 새 카드 + 새 카드 ➡️ 코인 2개

🌟 매 턴마다 바로 새 카드 더미에서 쓸 카드 정해 나머지 버리는 처리 할 필요 X ! 후보군이라 생각하고 전부 넣어뒀다가 쓰면 remove하고 코인 뺐음 ! 

---

✏️ 풀이 과정

1️⃣ 처음 n/3장의 카드를 my_deck에 저장

2️⃣ 매 라운드마다 반복문 돎 

↪️ 새로 카드 두 뽑아 new_deck에 저장

↪️ 갖고 있는 카드들 중 n+1 만들 수 있는 조합 찾아 있는 경우 true,  없는 경우 false 반환하는 isCardExist() 호출 

    => false인 경우 게임 종료이므로 break / true인 경우 round 수 추가 후 게임 다시 진행

3️⃣ isCardsExist() method에서는 합이 n+1이 되는 카드 조합 찾음

↪️ case 1. 코인 소모 0인 이미 손에 쥐고 있는 my_deck 안에서 찾기 -> 있다면 카드 2장 remove / return true
    
1-1. 소지한 코인 1개 미만이면 return false

↪️ case 2. 코인 소모 1인 my_deck에서 한 장 + new_deck에서 한 장 찾기 -> 있다면 카드 2장 remove / return true / coin -1 
    
 2-1. 소지한 코인 2개 미만이면 return false

↪️ case 3. 코인 소모 2인 new_deck에서 두 장 찾기 -> 있다면 카드 2장 remove / return true / coin -2 
    
3-1. 다 안 된다면 return false


## 3️⃣ 시간복잡도

`O(n²)`

각 카드 조합을 이중 반복문으로 탐색하므로 최악의 경우 `O(n²)`

## 4️⃣ 풀이하면서 실수했던 부분

카드를 사용한 뒤 ArrayList에서 두 카드를 삭제할 때 앞쪽 index부터 삭제하면 뒤쪽 카드의 index가 바뀐다는 점 모르고 풀었다 틀렸음 !

➡️ 같은 ArrayList에서 카드 2장을 삭제하는 경우 index가 더 큰 카드부터 remove 처리하도록 수정했음

## 5️⃣ 다시 푼다면 개선하고 싶은 점

현재는 카드 조합을 세 가지 케이스마다 이중 반복문을 돌며 직접 찾았는데, 다시 푼다면 n+1이 합이 되는 카드 쌍을 찾는 더 빠른 방법도 생각해 볼 것 같음 !
