# 접근 방법

- 카드의 합이 n + 1이 되는 두 장의 카드를 찾아 라운드를 진행한다.

- 현재 카드를 손에 가지고 있는 카드 `hand`와 공개되었지만 아직 사용하지 않은 카드 `extra`로 나누어 관리하였다.

- 각 라운드마다 새로운 카드 2장을 `extra`에 추가하고, 다음과 같은 우선순위로 카드 조합을 찾는다.

- 코인을 가장 적게 사용하는 조합부터 선택하여 최대한 많은 라운드를 진행하도록 하였다.

<br>

# 핵심 아이디어

- 각 카드 card가 있을 때 N + 1을 만들기 위해 필요한 카드의 값은 `n + 1 - card`이다.

- 각 라운드에서는 다음 순서로 탐색한다.
  1. hand ↔ hand
  2. hand ↔ extra
  3. extra ↔ extra

앞선 조합일수록 사용하는 코인이 적기 때문에 코인을 최대한 아끼면서 다음 라운드로 넘어가는 그리디 방식으로 해결하였다.


# 시간복잡도

각 라운드마다 hand 또는 extra를 순회하여 짝을 찾는다.

findPair()에서 Set을 순회하므로 한 번의 탐색은 최대 O(N)이고, 최대 O(N)번의 라운드가 진행될 수 있다.

따라서 전체 시간 복잡도는 O(N²)

HashSet.contains()는 평균 O(1)이므로 짝의 존재 여부 확인 자체는 효율적으로 수행할 수 있다.
