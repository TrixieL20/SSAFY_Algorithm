## 1️⃣ 문제 접근 방식
#### 📌 사용 알고리즘 - BFS

너비 우선 탐색하되 벽인 경우 이동하지 않게 처리하고 queue에 해당 지점까지의 총 이동 칸수를 함께 넣어 결과값 얻었음 ! 

## 2️⃣ 핵심 아이디어
🌟 boolean 배열 visited에 방문 여부 표시 ➡️ 이후 이동 시 중복된 길 가지 않게 체크

🌟 상하좌우 이동 나타내는 dir_x, dir_y ➡️ x, y에 더해 이동

🌟 이동 칸 수 따로 챙기는 대신 queue에 { x, y, 해당 (x, y)좌표까지 오기까지의 총 이동 칸수} 배열 넣음  

---
✏️ 풀이 과정

queue가 빌 때까지 반복문 내부에서

1️⃣ queue에서 빼낸 배열 pos(x, y, 해당 지점까지의 총 이동 칸 수)의 x와 y가 최종 목적지인 상대 진영의 x, y(m-1, n-1)과 같은 경우 도착한 상태이므로 현재까지의 이동거리인 pos[2] return

2️⃣ pos에서 상하좌우 이동한 4 개 모두에 대해
   
    ↪️ 이동 가능한 곳인지 검사 : 이미 방문한 경우 / [n x m] 범위 밖으로 나가는 경우 / 벽이 있어 이동할 수 없는 경우 ❌
   
    ↪️ 이동 가능한 곳이라면 visited true 처리 + queue에 이동 칸수 +1 해서 `{상하좌우 이동한 x, 상하좌우 이동한 y, pos[2] + 1)}` queue에 add
    
3️⃣ 1 거쳐 return 되지 않은 경우, 이동 경로 없는 것이므로 return -1
   
## 3️⃣ 시간복잡도
`O(m × n)`

## 4️⃣ 풀이하면서 실수했던 부분
도착 불가능한 경로인 경우 return -1 처리해 주는 부분 빠트려서 나중에 추가했음 !
