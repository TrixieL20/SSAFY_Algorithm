# 접근 방법

- 티켓을 순회하기 편하게 맵으로 만듦
- ICN에서 시작해서 만약 순회한 공항의 수가 티켓수 + 1이면 재귀를 멈추게 하는 DFS 메서드 구현
    - 반복문을 돌면서 해당 위치에서 갈 수 있는 곳을 탐색하고 이동한 공항에서 갈 수 있는 곳을 파악하고 끝까지 갔다가
더 갈 수 있는 곳이 없으면 기존의 것에서 다시 빼고 다른 공항을 탐색함

## 자료구조의 변천사
- Map<String, List<String>> ticketMap -> 출발지와 도착지가 같은 티켓이 있을 수 있음
- Map<String, Map<String, Integer>> ticketMap -> Integer라서 출발지와 도착지가 겹치는 티켓의 번호가 덮어쓰기 됨
- **Map<String, Map<String, List<Integer>>> ticketMap**

- Map<String, List<String>> visited -> 맵과 동일하게 형태를 만들어 방문 시 삽입하게 함
- **boolean[tickets.length]** -> 티켓 인덱스 기준으로 방문 여부 파악

# 어려웠던 점

* Map 구조를 쓰면 결국 중복되는 것들이 덮어쓰기 될 수 있는데 이 경우가 제대로 고려되지 않은 부분이 코드를 구현하면서 많이 나타나게 되어 여러번 구조를 수정하면서 어려움을 느꼈다.
  (Like 출발지와 도착지가 같은 티켓이 있을 수 있음)
* 자료구조를 계속 변경하다보니 이동했을 때 모든 티켓을 다 사용하지 않았지만 더 이상 이동할 수 없는 경우 재귀를 끊고 돌아오는 로직이 빠졌다.
* 41번째 줄에 paths.add(new ArrayList<>(path));를 원래 path를 add 하는 것으로 추가했었는데 그러면 해당 주소만 기록하는 것이어서 순회하면서 계속 값이 수정되어도 막을 수 없고 해당 값이 반영된다는 것을 생각하지 못했다.

<br>

# 배운 점

* arrayList의 값을 저장할 때 해당 값이 바뀔 가능성이 있다면 해당 값을 복사해서 새로운 객체를 만들고 저장해야 한다.
* Map을 쓸 때 어디까지 중복이 될 가능성이 있는 자료구조를 저장하는지 고려하고 자료구조를 설계해서 써야 할 것 같다.
