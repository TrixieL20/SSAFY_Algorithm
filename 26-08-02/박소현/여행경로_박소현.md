# 문제 접근 방식
DFS로 풀면 될 것이라고 생각했다.

# 핵심 아이디어
Map의 Key로 출발지, Value로 목적지 배열을 저장한 후 DFS를 하려고 했다.
이 때 방법이 여러가지가 있다면, 알파벳이 빠른 순으로 답을 작성해야 하기 때문에 Value 값인 배열을 정렬해주었다.

## 개선
Map으로 푸는 것보다 티켓 자체로 DFS로 시행하는 것이 더 정석적인 풀이였다.
여기서도 Visited 배열을 만드는 대신 tickets[i][0]의 값을 지워주는 방식을 택했다.

# 시간복잡도
O(N!) => 모든 공항이 전부 연결되어 있는 경우 모든 경우의 수를 탐색한다.

## 개선
O(N*N!) => dfs 호출 시, for문도 함께 동작하기 때문에 N*N!


# 풀이하면서 실수했던 부분
1. 문제에서 티켓을 다 사용하라고 했으나 까먹고 도시를 다 가는 방식으로 풀었다.
2. 무조건 출발지는 "ICN"으로 정해져 있는데 그 부분을 누락했다.

## 개선
1. answer를 remove(object o)로 지운다면, 앞에서부터 탐색하면서 o와 동일한 객체를 지워버린다.
   같은 도시가 있다면, 앞에 있는 도시 이름이 지워진다는 것을 놓쳤다.
