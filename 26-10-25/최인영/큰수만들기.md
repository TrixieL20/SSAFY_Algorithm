
## 1️⃣ 문제 접근 방식

#### 📌 사용 알고리즘 - 그리디 (Greedy)

앞자리 숫자가 클수록 전체 숫자가 커지므로, **앞에서부터 각 자리에 올 수 있는 가장 큰 숫자를 선택**하는 방식으로 접근했음 !

단, 현재 숫자를 선택한 뒤에도 나머지 자릿수를 채울 수 있어야 하므로 **각 자리에서 선택 가능한 인덱스 범위를 제한**해야 함

## 2️⃣ 핵심 아이디어

🌟 최종적으로 만들어야 하는 숫자의 길이는 `length - k`

🌟 `i`번째 숫자를 선택할 때, 이전에 선택한 숫자보다 뒤에 있는 숫자만 선택할 수 있음

🌟 뒤에 남은 자릿수까지 고려하면 `i`번째 숫자를 선택할 수 있는 인덱스 범위는

`preIdx + 1 <= j <= k + i`

- `preIdx` : 이전에 선택한 숫자의 인덱스 (초기값 `-1`)
- `k + i` : 뒤에 필요한 숫자를 모두 채울 수 있는 마지막 인덱스
- `i` : 현재 선택할 자리 (0부터 시작)

🌟 해당 범위에서 가장 큰 숫자를 선택하고, 그 인덱스를 `preIdx`에 저장

---

✏️ 풀이 과정

1. `length - k`개의 숫자를 앞자리부터 차례대로 선택
2. `i`번째 숫자를 선택하기 위해 `preIdx + 1`부터 `k + i`까지 탐색
3. 탐색 범위 내에서 가장 큰 숫자 `maxNum`과 해당 인덱스 `maxIdx` 저장
4. `maxIdx`를 `preIdx`로 갱신하고, 선택한 숫자를 `StringBuilder`에 추가
5. 모든 자리의 숫자를 선택하면 결과 반환 !

예를 들어 `number = "1924"`, `k = 2`인 경우

- `i = 0` : 인덱스 `0 ~ 2` 탐색 → `1, 9, 2` 중 `9` 선택 (인덱스 1)
- `i = 1` : 인덱스 `2 ~ 3` 탐색 → `2, 4` 중 `4` 선택 (인덱스 3)

최종 결과는 `"94"`

## 3️⃣ 시간복잡도

**최악의 경우 `O((n-k) × (k+1))` → `O(n²)`**

- 바깥 반복문 : 최종 숫자의 길이인 `n-k`번 반복
- 안쪽 반복문 : 각 자리에서 최대 `k+1`개의 숫자 탐색

`n`과 `k`가 모두 크면 탐색 횟수가 많아지므로 시간 초과 위험이 있음

실제 제출에서는 통과했지만, 입력 크기가 커지는 최악의 경우까지 고려하면 개선할 필요가 있음 !

## 4️⃣ 풀이하면서 실수했던 부분

**① 탐색 범위의 마지막 인덱스를 포함하지 않았음**

처음에는 `j < k+i`로 구현했는데, `k+i` 인덱스도 선택 가능한 범위이므로 `j <= k+i`로 수정해야 했음

**② char를 int로 저장하고 그대로 출력했음**

`number.charAt(j)`는 `char` 타입인데, 이를 `int maxNum`에 저장하면 문자의 코드값이 들어감

- `'9'` → `57`
- `'4'` → `52`

따라서 `sb.append(maxNum)`으로 추가하면 숫자 문자 대신 코드값이 문자열에 들어가는 문제가 발생했음

`sb.append((char) maxNum)`으로 형변환해서 해결 !

## 5️⃣ 다시 푼다면 개선하고 싶은 점

현재 풀이는 각 자리에서 가능한 범위를 매번 탐색하기 때문에 최악의 경우 `O(n²)`이 발생할 수 있음

**그리디 + 스택 방식으로 개선하면 `O(n)`으로 해결 가능 !**

🌟 앞자리부터 큰 숫자를 남긴다는 그리디 원칙은 동일하지만, 매번 최댓값을 탐색하는 대신 **현재 숫자보다 작은 이전 숫자를 제거**하는 방식

- 숫자를 앞에서부터 하나씩 확인
- 현재 숫자가 이전에 선택한 마지막 숫자보다 크면, 마지막 숫자를 제거
- 단, 제거 횟수가 `k`를 초과하면 안 됨
- 현재 숫자를 추가하고 다음 숫자로 이동
- 마지막까지 확인했는데 제거 횟수가 남았다면, 뒤에서 남은 개수만큼 제거

`StringBuilder`를 스택처럼 활용하면 별도의 스택 자료구조 없이 구현할 수 있음

각 숫자는 최대 한 번 추가되고 한 번 제거되므로 **시간 복잡도 `O(n)`**

다음에 푼다면 숫자를 직접 선택하는 방식뿐만 아니라, **작은 숫자를 제거해서 큰 숫자를 남기는 방식**도 생각해 보면 좋을 듯함 !
