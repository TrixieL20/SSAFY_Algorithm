| 난이도 | D3 |
| 플랫폼 | SWEA 1244 |

# 접근 방법

숫자판에서 두 자리를 선택해 정해진 횟수만큼 교환한 뒤 만들 수 있는 가장 큰 수를 구해야 한다.

숫자판은 최대 6자리이므로 한 번의 교환에서 선택할 수 있는 두 자리의 조합은 최대 다음과 같다.

$$
\binom{6}{2} = 15
$$

처음에는 각 교환마다 가능한 모든 두 자리 조합을 DFS로 탐색하면 된다고 생각했다.

하지만 교환 횟수가 최대 10번이므로 단순 완전탐색의 경우 최대

$$
15^{10} = 576,650,390,625
$$

개의 경로가 만들어질 수 있어 그대로 탐색하기에는 경우의 수가 너무 많다.

다만 서로 다른 탐색 경로를 통해 동일한 숫자 상태가 반복해서 만들어진다.

숫자가 6자리일 때 만들 수 있는 서로 다른 자리 배치 자체는 중복 숫자가 없다고 해도 최대 `6! = 720`개뿐이다.

따라서 **현재 교환 횟수(depth)에서 이미 탐색한 숫자 상태라면 다시 탐색하지 않는 방식**으로 중복을 제거한다.

DFS에서는 모든 `(i, j)` 쌍을 교환하고 다음 깊이로 이동한 뒤 다시 원래 상태로 복구하는 백트래킹을 사용한다.

# 자료구조

* `char[] arr`
  * 현재 숫자판의 상태를 저장한다.
  * 두 위치의 값을 직접 `swap`하기 위해 사용한다.

* `Set<String>[] visited`
  * 각 교환 횟수별로 이미 탐색한 숫자 상태를 저장한다.
  * `visited[depth]`에는 정확히 `depth`번 교환했을 때 만들어진 숫자들이 저장된다.

* `int max`
  * 정확히 주어진 횟수만큼 교환했을 때 만들어진 숫자 중 최댓값을 저장한다.

# 핵심 아이디어

### 1. 모든 두 자리 조합을 교환

숫자의 길이가 `L`이라면 한 번의 교환에서 가능한 모든 두 자리 조합을 확인한다.

```java
for (int i = 0; i < arr.length - 1; i++) {
    for (int j = i + 1; j < arr.length; j++) {
        swap(i, j);
        dfs(depth + 1);
        swap(i, j);
    }
}
```

교환한 뒤 재귀 호출을 하고, 다음 경우의 수를 확인하기 위해 반드시 원래 상태로 복구한다.

### 2. 같은 깊이의 동일한 숫자 상태는 한 번만 탐색

예를 들어 서로 다른 교환 순서를 거쳐 같은 숫자가 만들어질 수 있다.

```text
123456
  ↓
213456
  ↓
231456

123456
  ↓
132456
  ↓
231456
```

두 경로 모두 같은 교환 횟수에서 `231456`이라는 상태에 도달했다면 이후 만들어지는 경우의 수 역시 동일하다.

따라서 같은 깊이에서 이미 탐색한 상태라면 더 이상 내려가지 않는다.

```java
String current = new String(arr);

if (!visited[depth].add(current)) {
    return;
}
```

### 3. 방문 여부에 교환 횟수까지 포함

숫자 상태만 기준으로 방문 처리하면 안 된다.

```text
0번 교환한 123
2번 교환한 123
```

은 숫자 자체는 같지만 남아 있는 교환 횟수가 서로 다르다.

문제에서는 **반드시 주어진 횟수만큼 교환해야 하므로** `(교환 횟수, 현재 숫자)`를 하나의 상태로 생각해야 한다.

그래서 하나의 `Set`이 아니라 깊이별 `Set`을 사용한다.

```java
visited[depth].contains(current)
```

### 4. 정확히 N번 교환했을 때만 최댓값 갱신

```java
if (depth == N) {
    int result = Integer.parseInt(new String(arr));
    max = Math.max(max, result);
    return;
}
```

중간에 더 큰 숫자가 만들어졌더라도 교환 횟수가 남아 있다면 그대로 정답으로 사용할 수 없다.

# 시간복잡도

중복 제거 없이 모든 교환을 탐색하면 숫자가 6자리이고 교환 횟수가 10번일 때 최대

$$
15^{10}
$$

개의 경로를 탐색하게 된다.

하지만 깊이별 중복 상태를 제거하면 한 깊이에서 존재할 수 있는 서로 다른 숫자 배치는 최대

$$
6! = 720
$$

개이다.

각 상태에서 최대 `15`개의 교환을 확인하고 교환 횟수가 최대 `10`번이므로 대략

$$
O(K \times 6! \times \binom{6}{2})
$$

로 볼 수 있다.

최대 조건에서는 약 `10 × 720 × 15` 수준의 상태 전이를 확인하므로 충분히 탐색 가능하다.

# 배운 점

* 재귀의 분기 수만 보고 완전탐색 가능 여부를 판단하는 것이 아니라 **실제로 존재하는 서로 다른 상태의 수**도 함께 확인해야 한다.
* 서로 다른 경로가 같은 상태로 합쳐지는 문제에서는 `visited`를 이용해 중복 탐색을 크게 줄일 수 있다.
* 같은 숫자라도 현재까지 사용한 교환 횟수가 다르면 이후 가능한 결과가 달라지므로 `depth`까지 상태에 포함해야 한다.
* DFS에서 배열을 직접 변경한다면 재귀 호출 이후 반드시 원래 상태로 복구해야 한다.
* 문제에서 "정해진 횟수만큼 반드시 교환"이라고 했으면 최댓값이 만들어졌다는 이유만으로 탐색을 조기에 종료하면 안 된다.

# 실수한 부분

### 1. 처음에는 모든 교환을 그대로 탐색하려고 함

숫자가 최대 6자리이므로 한 번 교환할 때 가능한 경우는 최대 15개라서 작아 보였다.

하지만 교환 횟수가 최대 10번이므로 단순 DFS의 경우

$$
15^{10} = 576,650,390,625
$$

까지 증가한다.

따라서 같은 깊이에서 같은 숫자 상태를 다시 탐색하지 않도록 중복 제거가 필요하다.

### 2. 교환 횟수를 자릿수로 단순 축소하면 안 됨

처음 코드에서는 다음과 같이 교환 횟수가 자릿수보다 크면 자릿수까지만 탐색하도록 했다.

```java
if (arr.length < N) {
    N = arr.length;
}
```

하지만 문제에서는 정확히 `N`번 교환해야 한다.

특히 모든 숫자가 서로 다른 경우에는 교환 횟수의 홀짝에 따라 도달할 수 있는 순열이 달라질 수 있기 때문에 단순히 `N = arr.length`로 줄이면 정답이 달라질 수 있다.

따라서 원래 교환 횟수를 유지하고, 깊이별 중복 상태 제거로 탐색량을 줄이는 방식이 안전하다.

### 3. `start` 매개변수가 실제 탐색에 사용되지 않음

초기 코드의

```java
DFS(int start, int depth)
```

에서 `start`는 재귀 내부의 반복문 범위를 제한하는 데 사용되지 않았다.

모든 깊이에서 전체 `(i, j)` 조합을 다시 확인해야 하는 문제이므로 최종 코드에서는 `depth`만 전달하도록 단순화했다.
