# 문제 정보

| 항목    | 내용          |
| ----- |-------------|
| 문제 이름 | 전력망을 둘로 나누기 |
| 난이도   | Lv2         |
| 플랫폼   | 프로그래머스      |

<br>

# 접근 방법
- 전력망은 모든 송전탑이 연결되어 있고 사이클이 없는 `트리` 구조이다.
- 전선 하나를 끊으면 전력망이 반드시 두 개의 연결된 그룹으로 나뉜다.
- 모든 전선을 하나씩 끊었다고 가정하고, `DFS`를 이용해 한쪽 전력망에 포함된 송전탑의 개수를 구한다.
- 한쪽 송전탑의 개수가 `count`라면 다른 쪽의 송전탑 개수는 `n - count`로 구할 수 있다.
- 두 전력망의 송전탑 개수 차이인 `Math.abs(count - (n - count))`를 계산하여 최솟값을 갱신한다.

## 자료구조
- `List<Integer>[] graph` : 송전탑 사이의 연결 관계를 저장하는 인접 리스트
- `boolean[] visited` : DFS 탐색 중 방문한 송전탑을 확인
- `int count` : 현재 연결된 전력망에 포함된 송전탑의 개수
- `int[][] wires` : 송전탑을 연결하는 전선 정보

<br>

# 핵심 아이디어

* 전력망이 `트리`이기 때문에 전선 하나를 제거하면 반드시 두 개의 전력망으로 나뉜다.
* 전선을 실제로 삭제하지 않고, DFS 탐색 중 현재 끊었다고 가정한 전선을 만나면 `continue`하여 이동하지 않는다.
* 한쪽 전력망의 송전탑 개수만 DFS로 구하면 다른 쪽은 `전체 송전탑 개수 - 현재 송전탑 개수`로 구할 수 있다.
* 전선은 양방향이므로 cutA → cutB뿐만 아니라 cutB → cutA도 탐색하지 않도록 처리해야 한다.

<br>

# 시간복잡도
O(N²)

# 배운 점
- 트리에서는 간선 하나를 제거하면 두 개의 연결 요소로 나뉜다는 특징을 활용할 수 있다.
- DFS는 단순히 경로를 찾는 것뿐만 아니라 연결된 정점의 개수를 세는 데에도 사용할 수 있다.
- 그래프에서 특정 간선을 제거해야 하는 경우 실제로 삭제하지 않고, 탐색 과정에서 해당 간선을 건너뛰는 방식으로 구현할 수 있다.
- 한쪽 전력망의 크기가 count라면 다른 쪽은 n - count이므로 두 번 탐색할 필요가 없다.

# 실수한 부분
- 전선을 끊는다는 의미 때문에 실제 인접 리스트에서 간선을 삭제해야 한다고 생각할 수 있지만, DFS에서 해당 전선만 탐색하지 않아도 된다.
- 전선은 양방향이기 때문에 끊은 전선을 확인할 때 두 방향을 모두 확인해야 한다.
- 전선 하나마다 새로운 DFS를 수행하므로 visited와 count를 매번 초기화해야 한다.
