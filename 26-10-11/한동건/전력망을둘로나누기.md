# 접근 방법 / 핵심 아이디어
- 트리에서 간선 하나를 끊으면 **정확히 두 개의 컴포넌트**로 나뉜다.
- n ≤ 100이므로 **모든 간선을 하나씩 끊어보는 완전탐색**이 가능하다.
- 풀이 흐름
  1. `ArrayList<Integer>[]` 인접 리스트로 무방향 그래프 구성
  2. i번째 간선을 양방향 모두 `remove`로 제거
  3. 끊긴 간선의 양 끝점(left, right)에서 각각 BFS → 각 컴포넌트 크기 계산
  4. `|left_cnt - right_cnt|`로 최솟값 갱신
  5. 간선을 다시 `add`로 복구 (끊기 → 세기 → 복구, 백트래킹 패턴)
- 개선: 트리이므로 `오른쪽 크기 = n - 왼쪽 크기` → BFS 1번이면 충분
- 최적 풀이: 루트에서 DFS 1번으로 서브트리 크기 `sz[v]`를 구하면, 간선 (부모, v)를 끊었을 때 차이는 `|n - 2·sz[v]|` → O(n)
<br>

# 시간복잡도
- 간선 (n-1)개 × (BFS O(n) × 2 + remove O(차수)) → **O(n²)**
- n = 100 기준 약 2×10⁴ 연산 → 제한시간 여유
- 공간: 인접 리스트 + 방문 배열 + 큐 → **O(n)**
- 참고: 서브트리 크기 DFS 풀이는 **O(n)** (n이 10⁵ 이상이면 이 방법만 통과)
