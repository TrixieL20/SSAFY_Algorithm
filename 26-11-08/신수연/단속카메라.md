# 문제 정보

| 항목 | 내용 |
| ----- | ------ |
| 문제 이름 | 단속카메라 |
| 난이도 | Lv. 3 |
| 플랫폼 | Programmers |



## 접근 방법

- 차량의 이동 경로를 진입 지점 기준으로 오름차순 정렬한다.
- 카메라 한 대로 단속할 차량들을 하나의 그룹으로 묶는다. 그룹에 속한 모든 차량의 경로가 공통으로 겹쳐야 한다.
- `minEnd`는 현재 그룹의 진출 지점 중 최솟값으로, 공통 구간의 오른쪽 끝을 의미한다.
- 첫 번째 차량으로 그룹을 시작하고 `count = 1`, `minEnd = routes[0][1]`로 초기화한다.
- 이후 차량을 순회하며 두 가지 경우로 나눈다.
  - `routes[i][0] <= minEnd`: 현재 그룹과 공통 구간이 있으므로 같은 카메라로 단속할 수 있다. `minEnd`를 현재 차량의 진출 지점과 비교해 더 작은 값으로 갱신한다.
  - `routes[i][0] > minEnd`: 공통 구간이 없어 기존 그룹과 함께 단속할 수 없다. 카메라 수를 하나 늘리고 현재 차량으로 새 그룹을 시작한다.
- 모든 차량을 확인한 뒤 `count`를 반환한다.

## 핵심 아이디어

- **정렬과 그리디를 이용해 공통 구간이 유지되는 동안 최대한 같은 카메라로 묶는다.** 진입 지점이 오름차순이므로 현재 차량의 진입 지점은 현재 그룹에서 가장 큰 진입 지점이다. 따라서 이 값이 `minEnd` 이하인지 확인하는 것만으로 공통 구간의 존재를 판단할 수 있다.
- **`minEnd`는 직전 차량의 진출 지점이 아니라 그룹 전체의 최소 진출 지점이다.** 직전 차량과만 비교하면 앞선 차량을 놓칠 수 있다. 예를 들어 `[1, 4]`, `[2, 8]`, `[5, 9]`는 인접한 경로끼리는 겹치지만 세 경로 전체가 겹치는 지점은 없다.
- **공통 구간이 사라질 때 카메라 추가는 반드시 필요하다.** 현재 그룹에서 `minEnd`에 진출하는 차량과 새 차량은 경로가 겹치지 않으므로 같은 카메라로 단속할 수 없다. 기존 그룹의 카메라를 `minEnd`에 두고 새 그룹을 시작하면 된다. 이는 기존 그룹을 모두 단속할 수 있는 가장 오른쪽 위치이므로 이후 차량을 함께 단속할 가능성도 최대한 유지한다. 이 선택을 반복하면 최소 개수를 얻는다.
- **끝점이 같으면 같은 카메라를 사용할 수 있다.** 진입·진출 지점에서도 단속되므로 겹침 조건에 `<=`를 사용한다.
- 원본 코드의 새 그룹 처리에서 `Math.max(minEnd, routes[i][1])`는 올바르게 동작한다. 이 분기에서는 `minEnd < routes[i][0] <= routes[i][1]`이므로 항상 현재 차량의 진출 지점이 선택된다. 따라서 `minEnd = routes[i][1]`로 간단히 작성해도 결과는 같다.

## 시간복잡도

- 시간복잡도: **O(N log N)**
  - N은 차량의 수이다. 진입 지점 정렬에 O(N log N), 전체 차량 순회에 O(N)이 걸린다.

- 공간복잡도: **O(N)**
  - Java에서 `int[][]`를 비교자로 정렬하면 각 `int[]`를 원소로 갖는 객체 배열 정렬이 적용되므로 정렬 과정에서 최악 O(N)의 보조 공간을 사용한다.
  - 정렬을 제외한 순회 과정의 추가 공간은 `minEnd`, `count` 등 변수만 사용하므로 O(1)이다.
