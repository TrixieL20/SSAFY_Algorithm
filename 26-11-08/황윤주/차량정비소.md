# 문제 정보

| 항목 | 내용 |
|---|---|
| 문제 이름 | 차량 정비소  |
| 난이도 | D3 |
| 플랫폼 | SWEA |
| 사용 알고리즘 | 시뮬레이션, 큐(Queue) |

<br>

# 접근 방법

- 처음에는 아이디어 자체가 떠오르지 않아 입력만 받고 구현을 시작하지 못했다.
- 접수 대기와 정비 대기를 각각 큐로 관리하고, 창구 상태는 배열로 관리했다.
- 시간을 1씩 증가시키며 고객 도착, 접수 완료, 정비 완료, 빈 창구 배정을 처리했다.

<br>

# 핵심 아이디어

- `receptionWait`, `repairWait` 큐를 이용해 대기 고객을 관리한다.
- `receptionEnd`, `repairEnd` 배열에 각 창구의 업무 종료 시간을 저장한다.
- 접수가 완료된 고객은 접수 창구 번호가 작은 순서대로 정비 대기 큐에 넣는다.
- 빈 창구가 생기면 대기 큐에서 `poll()`로 고객을 꺼내 배정한다.
- 특정 접수 창구 A와 정비 창구 B를 모두 이용한 고객 번호를 합산한다.

<br>

# 시간복잡도

**O(T × (N + M) + K)**

- T : 마지막 고객의 정비가 완료되는 시간
- N : 접수 창구 수
- M : 정비 창구 수
- K : 고객 수

<br>

# 배운 점

- 시뮬레이션 문제에서 큐를 활용해 대기 순서를 관리하는 방법을 익혔다.
- 현재 시간과 작업 종료 시간을 비교해 창구 상태를 변경하는 방식을 배웠다.
- 복잡한 시뮬레이션은 단계별로 나누어 구현해야 한다는 것을 느꼈다.

<br>

# 실수한 부분

- 처음에는 어떤 자료구조를 사용해야 할지 몰라 아이디어 구상부터 막혔다.
- 고객 번호는 1부터 시작하지만 도착 시간 배열은 0부터 저장해 인덱스가 어긋났다.
