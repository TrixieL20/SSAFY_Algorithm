# 프로그래머스 42884 - 단속카메라

## 1. 문제 접근 방식

- 모든 차량이 최소 한 번 이상 단속카메라를 만나도록 하는 **최소 카메라 개수**를 구하는 그리디 문제
- 차량의 진입 지점을 기준으로 오름차순 정렬한 뒤, 카메라를 공유할 수 있는 구간을 관리하는 방식으로 접근
- 카메라 위치를 바로 정하지 않고, 여러 차량이 공통으로 지나는 **구간의 교집합**을 유지
- 새로운 차량의 이동 구간이 기존 카메라 설치 가능 구간과 겹치지 않으면 새로운 구간 추가

## 2. 핵심 아이디어

### ① 차량 진입 지점 기준 정렬

- 차량의 진입 지점을 기준으로 오름차순 정렬
- 진입 지점이 같으면 진출 지점 기준으로 정렬
- 정렬된 순서대로 차량을 확인하며 카메라 설치 가능 구간을 갱신

### ② 카메라 설치 가능 구간 관리

- `cameras` 리스트에 카메라를 설치할 수 있는 구간을 저장
- 새로운 차량의 이동 구간과 기존 구간이 겹치는지 확인
- 겹친다면 두 구간의 **교집합으로 범위를 갱신**

```java
cameras.get(j)[0] = Math.max(cameras.get(j)[0], routes[i][0]);
cameras.get(j)[1] = Math.min(cameras.get(j)[1], routes[i][1]);
```

- 교집합이 존재하면 해당 구간에 카메라 하나를 설치하여 여러 차량을 단속할 수 있음

### ③ 새로운 카메라 구간 추가

- 기존 카메라 설치 가능 구간과 겹치지 않는다면 새로운 구간 추가
- 모든 차량을 확인한 뒤 `cameras.size()` 반환

## 3. 시간복잡도

- 차량 진입 지점 기준 정렬: `O(N log N)`
- 각 차량에 대해 기존 카메라 구간 탐색: `O(N²)`

**전체 시간복잡도: `O(N²)`**

- N: 차량의 수
- 공간복잡도: `O(N)` (카메라 구간 리스트)

## 4. 풀이하면서 고려하거나 헷갈릴 수 있는 부분

- **카메라 설치 위치:** 실제 좌표를 바로 결정하는 대신, 카메라를 설치할 수 있는 공통 구간을 유지하는 방식으로 접근
- **교집합 갱신:** 두 구간이 겹친다고 기존 구간을 그대로 유지하면 안 됨. 모든 차량이 공통으로 지나는 범위로 좁혀야 함
- **구간 비교:** `routes[i][1] < cameras.get(j)[0]` 또는 `routes[i][0] > cameras.get(j)[1]`일 때만 겹치지 않는 것으로 판단. 진입·진출 지점이 같아도 단속 가능
- **정렬 기준:** 진입 지점을 기준으로 정렬하므로 앞에서 처리한 구간과의 관계를 순서대로 관리할 수 있음
- **배열 참조:** `cameras.add(routes[i])`는 배열을 복사하는 것이 아니라 참조를 저장하므로, 교집합 갱신 시 원본 `routes` 배열도 변경됨

## 5. 다시 푼다면 개선하고 싶은 점

- 현재는 각 차량마다 기존 카메라 구간을 탐색하므로 최악의 경우 `O(N²)`이 발생
- **진출 지점을 기준으로 오름차순 정렬**하면 더 간단한 그리디 방식으로 개선 가능
- 가장 먼저 진출하는 차량의 진출 지점에 카메라를 설치하고, 이후 차량이 해당 카메라를 지나지 않는 경우에만 새로운 카메라 설치
- 이를 통해 별도의 구간 리스트 없이 `O(N log N)`에 해결 가능

여러 차량의 이동 구간에서 교집합을 유지하면 카메라 하나로 단속할 수 있는 차량들을 묶을 수 있음. 다만 진출 지점 기준 그리디를 활용하면 더 효율적으로 해결할 수 있음.
