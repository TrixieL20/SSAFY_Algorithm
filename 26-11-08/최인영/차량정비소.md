# SWEA 2477 - 차량 정비소

## 1. 문제 접근 방식

- 고객이 접수 창구를 거쳐 정비 창구를 이용하는 과정을 **시뮬레이션**하는 문제
- 시간을 1씩 증가시키는 대신, 각 창구의 **서비스 종료 시간**을 관리하는 방식으로 접근
- 접수와 정비는 독립적으로 진행되므로 모든 고객의 접수를 먼저 처리한 뒤, 접수 완료 순서대로 정비를 처리
- 각 고객이 이용한 접수·정비 창구 번호를 저장하고, 목표 창구와 모두 일치하는 고객 번호를 합산

## 2. 핵심 아이디어

### ① 접수 창구 배정

- 고객의 방문 시간보다 종료 시간이 빠르거나 같은 창구가 있다면, 번호가 가장 작은 창구에 배정
- 모든 창구가 사용 중이면 **가장 먼저 종료되는 창구**에 배정
- 접수 완료 시간과 이용한 접수 창구 번호를 고객 객체에 저장

### ② 접수 완료 순서 정렬

정비 창구의 대기 우선순위를 반영하기 위해 고객 리스트를 정렬

1. 접수 완료 시간이 빠른 고객 우선
2. 접수 완료 시간이 같으면 접수 창구 번호가 작은 고객 우선

### ③ 정비 창구 배정

- 접수 완료 시간을 기준으로 이용 가능한 정비 창구 탐색
- 여러 창구가 비어 있다면 번호가 작은 창구 선택
- 모두 사용 중이면 가장 먼저 종료되는 창구 선택
- 이용한 정비 창구 번호를 고객 객체에 저장

### ④ 결과 계산

- 목표 접수 창구 `a`, 정비 창구 `b`를 모두 이용한 고객 번호 합산
- 해당 고객이 없다면 `-1` 출력

## 3. 시간복잡도

- 접수 창구 배정: `O(K × N)`
- 고객 정렬: `O(K log K)`
- 정비 창구 배정: `O(K × M)`

**전체 시간복잡도: `O(K(N + M) + K log K)`**

- K: 고객 수
- N: 접수 창구 수
- M: 정비 창구 수

## 4. 풀이하면서 고려하거나 실수했던 부분

- **시뮬레이션 방식:** 시간을 1씩 증가시키지 않고 창구별 종료 시간을 저장해도 되는지 고민했음. 접수와 정비를 분리해 처리할 수 있다는 점을 활용
- **대기 우선순위:** 접수 완료 시간이 같은 고객은 접수 창구 번호가 작은 순서로 정렬해야 한다는 점을 고려
- **정비 대상:** 목표 접수 창구를 이용한 고객만 정비 과정을 계산하려 했지만, 다른 고객이 정비 창구를 점유할 수 있으므로 모든 고객을 처리해야 함
- **배열 참조:** 정비 단계에서 접수 창구 개수 `n`과 정비 창구 개수 `m`, 접수·정비 처리 시간 배열을 혼동했음
- **고객 번호:** 조건에 해당하는 고객 수가 아닌 고객 번호의 합을 구해야 하며, 고객 번호는 1부터 시작함
- **입력 처리:** 접수 시간, 정비 시간, 방문 시간은 서로 다른 줄에 주어지므로 `StringTokenizer`를 새로 생성해야 함

## 5. 다시 푼다면 개선하고 싶은 점

- `Customer.repairTime`은 실제로 접수 완료 시간을 의미하므로 `receptEndTime`으로 변경
- 사용하지 않는 `targetRecept` 리스트 제거
- 접수·정비 과정에서 중복되는 창구 탐색 로직을 메서드로 분리해 가독성 개선
- `charAt(0) - '0'` 대신 `Integer.parseInt()`를 사용해 입력 처리 통일
