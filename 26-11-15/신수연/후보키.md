# 접근 방법

후보키가 되기 위해서는 **유일성**과 **최소성**을 모두 만족해야 한다.

- **유일성**: 선택한 속성들의 조합으로 모든 튜플을 유일하게 식별할 수 있어야 한다.
- **최소성**: 후보키를 구성하는 속성 중 하나라도 제거하면 유일성을 만족하지 못해야 한다.

DFS와 백트래킹을 이용해 속성의 모든 조합을 생성하고, 각 조합이 후보키 조건을 만족하는지 검사한다.

### 1. DFS를 이용한 속성 조합 생성

- 속성의 개수를 1개부터 전체 열 개수까지 증가시키며 조합을 생성한다.
- `visited`에는 현재 선택한 속성의 인덱스를 저장한다.
- `depth == max`가 되면 원하는 개수만큼 속성을 선택한 것이므로 후보키 조건을 검사한다.
- 재귀 호출 이후 `visited.remove(i)`를 통해 선택한 속성을 제거하고 다른 조합을 탐색한다.

예를 들어 속성이 4개라면 다음과 같이 탐색한다.

```text
속성 1개: {0}, {1}, {2}, {3}

속성 2개: {0,1}, {0,2}, {0,3},
          {1,2}, {1,3}, {2,3}

속성 3개: {0,1,2}, {0,1,3},
          {0,2,3}, {1,2,3}

속성 4개: {0,1,2,3}
```

### 2. 최소성 검사

```java
for (Set<Integer> key : keys) {
    if (visited.containsAll(key)) return;
}
```

- `keys`에는 이미 발견한 후보키들이 저장되어 있다.
- 현재 조합 `visited`가 기존 후보키를 모두 포함하고 있다면 최소성을 만족하지 않는다.
- 따라서 해당 조합은 유일성을 검사할 필요 없이 종료한다.

예를 들어 `{0, 2}`가 이미 후보키라면 `{0, 1, 2}`는 최소성을 만족하지 않는다.

**속성 개수가 적은 조합부터 검사하기 때문에 기존 후보키를 포함하는지만 확인하면 된다.**

### 3. 유일성 검사

```java
Set<String> set = new HashSet<>();

for (int i = 0; i < relation.length; i++) {
    StringBuilder sb = new StringBuilder();

    for (int v : visited) {
        sb.append(relation[i][v]).append(",");
    }

    if (!set.add(sb.toString())) {
        return;
    }
}
```

- 각 행에서 현재 선택한 속성들의 값을 하나의 문자열로 결합한다.
- 결합한 문자열을 `HashSet`에 저장한다.
- `HashSet.add()`는 중복된 값이 존재하면 `false`를 반환한다.
- 중복이 발생했다면 서로 다른 튜플을 구별할 수 없으므로 유일성을 만족하지 않는다.
- 모든 행의 조합이 중복 없이 저장되었다면 유일성을 만족한다.

유일성과 최소성을 모두 만족한 조합은 후보키 목록에 추가한다.

```java
keys.add(new HashSet<>(visited));
```

# 핵심 아이디어

- **DFS + 백트래킹**: 모든 속성 조합을 생성하고 탐색 후 선택한 속성을 제거하여 다른 조합을 탐색한다.
- **조합 크기 오름차순 탐색**: 속성 개수가 적은 조합부터 검사하여 최소성 판단을 쉽게 한다.
- **최소성 검사**: `containsAll()`을 이용해 현재 조합이 기존 후보키를 포함하는지 확인한다.
- **유일성 검사**: `HashSet`을 이용해 각 튜플의 속성 조합이 중복되는지 확인한다.
- **후보키 저장**: 두 조건을 모두 만족한 속성 조합만 `keys`에 저장한다.

- **공간복잡도: O(R × C + C × 2^C)**
