# 접근 방법 / 핵심 아이디어

**1. 백트래킹을 이용한 계단 배정**

- 각 사람은 두 개의 계단 중 하나를 선택할 수 있으므로, 백트래킹으로 모든 배정 경우의 수를 탐색한다.
- `peopleStairs[]` 배열에 각 사람이 이용할 계단 번호(0 또는 1)를 저장한다.
- `selectStairs(idx)`에서 현재 사람을 0번 계단에 배정하는 경우와 1번 계단에 배정하는 경우를 재귀적으로 탐색한다.
- 모든 사람의 계단 배정이 완료되면 각 계단을 이용하는 데 걸리는 시간을 계산한다.

**2. 계단별 이동 시간 계산**

- `moveDownStairs(stairIdx)`에서 해당 계단을 선택한 사람만 추출한다.
- 사람과 계단 사이의 맨해튼 거리를 계산하여 계단 입구까지 도착하는 시간을 구한다.
- 사람들이 계단에 도착하는 순서대로 처리할 수 있도록 거리 기준 오름차순 정렬한다.
- 계단 입구에 도착한 후 1분이 지나야 내려갈 수 있으므로 최초 입장 가능 시간은 `dist + 1`이다.

**3. 계단의 최대 수용 인원 3명 처리**

- 처음에는 계단에 있는 사람 수를 직접 세면서 시뮬레이션하려고 했으나, 사람이 계단을 빠져나오는 시점을 관리해야 한다는 문제가 있었다.
- 이를 해결하기 위해 `finish[]` 배열에 각 사람이 계단을 완전히 내려온 시간을 저장하는 방식으로 구현했다.
- 처음 3명은 입장 가능 시간이 되면 바로 내려갈 수 있다.
- 4번째 사람부터는 자신보다 3명 앞서 입장한 사람이 계단을 빠져나와야 내려갈 수 있다.
- 따라서 `i >= 3`인 경우 실제 계단 입장 시작 시간은 `Math.max(dist + 1, finish[i - 3])`으로 계산한다.
- 각 사람의 최종 완료 시간은 `start + stair[2]`로 계산한다.

**4. 전체 소요 시간 및 최솟값 갱신**

- 두 계단은 동시에 이용할 수 있으므로 전체 소요 시간은 두 계단의 완료 시간 중 최댓값이다.
- 모든 계단 배정 경우에 대해 `Math.max(moveDownStairs(0), moveDownStairs(1))`을 계산한다.
- `minTime`에 전체 소요 시간의 최솟값을 갱신한다.

# 시간복잡도

**O(2^P × P log P)** (P: 사람 수)

- 계단 배정: 각 사람이 2개의 계단 중 하나를 선택하므로 `O(2^P)`
- 이동 시간 계산 및 정렬: 각 배정에서 사람들의 도착 시간을 계산하고 정렬하므로 `O(P log P)`
- 계단 이용 시간 계산: 정렬된 사람들을 순회하므로 `O(P)`
- 전체 시간복잡도: `O(2^P × P log P)`

사람 수가 최대 10명이므로 최대 1024개의 배정 경우를 탐색하며, 제한 시간 내에 충분히 해결할 수 있다.

<br>

# 어려웠던 점 / 배운점

**1. 계단에 동시에 최대 3명만 내려갈 수 있다는 조건 처리**

- 처음에는 `people < 3` 조건을 사용하여 현재 계단을 이용하는 사람 수를 관리하려고 했다.
- 하지만 단순히 인원 수를 증가시키는 방식으로는 사람이 언제 계단을 빠져나오는지 알 수 없어 대기 시간을 계산하기 어려웠다.
- 각 사람의 계단 이용 완료 시간을 저장하면 현재 계단에 있는 사람 수를 직접 관리하지 않아도 된다는 점을 배웠다.
- 특히 `finish[i - 3]`을 이용하면 대기 여부를 간단하게 계산할 수 있다는 점이 핵심이었다.

**2. 계단에 도착하는 시간과 실제 내려가기 시작하는 시간의 차이**

- 계단 입구에 도착하자마자 내려가는 것이 아니라 1분 후부터 내려갈 수 있다는 조건을 고려해야 했다.
- 계단에 빈자리가 없다면 `dist + 1`이 지나더라도 대기해야 하므로, 실제 시작 시간은 이전 사람의 완료 시간과 비교하여 결정해야 한다.

**3. 계단을 선택한 사람이 없는 경우 처리**

- 백트래킹으로 모든 배정을 탐색하면 모든 사람이 하나의 계단만 선택하는 경우도 발생한다.
- 이때 다른 계단의 `finish[]` 배열 크기가 0이 되어 마지막 원소에 접근하면 `ArrayIndexOutOfBoundsException`이 발생한다.
- 따라서 해당 계단을 선택한 사람이 없을 경우 0을 반환하도록 예외 처리를 추가했다.

**4. 두 계단의 소요 시간 계산**

- 두 계단은 독립적으로 동시에 이용되므로 완료 시간을 더하는 것이 아니라 최댓값을 구해야 한다.
- 백트래킹에서는 각 경우의 수를 생성하고, 시뮬레이션에서는 해당 경우의 결과를 계산하도록 역할을 분리할 수 있었다.

**5. 배운 점**

- 백트래킹으로 모든 경우의 수를 탐색하고, 각 경우에 대해 시뮬레이션을 수행하는 문제 해결 방식을 연습했다.
- 시간에 따라 상태가 변하는 문제라도 반드시 매분 상태를 갱신할 필요는 없으며, 완료 시각을 기록하는 방식으로 시뮬레이션을 단순화할 수 있다는 것을 배웠다.
- 경계 조건(특정 계단 이용 인원 0명)을 빠뜨리지 않고 확인하는 것이 중요하다는 점을 알게 되었다.
