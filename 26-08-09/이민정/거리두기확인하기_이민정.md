# 문제 정보

| 항목    | 내용          |
| ----- |-------------|
| 문제 이름 | 거리두기 확인하기   |
| 난이도   | Level 2     |
| 플랫폼   | Programmers |

<br>

# 접근 방법

- 각 대기실의 모든 `P`를 시작점으로 하여 **BFS**를 수행했다.
- 한 사람(`P`)으로부터 맨해튼 거리 2 이내에 다른 `P`가 존재하는지 확인한다.
- 단순히 거리가 2 이내인지만 확인하는 것이 아니라 **중간에 파티션(`X`)이 존재하면 해당 경로는 이동할 수 없는 것으로 처리**한다.
- 따라서 각 `P`를 시작점으로 상하좌우를 탐색하면서 이동 거리를 `visited` 배열에 기록하고 거리 2 이내에서 다른 `P`를 발견하면 해당 대기실은 거리두기를 지키지 않은 것으로 판단했다.

# 핵심 아이디어

- 맨해튼 거리는 두 점 `(x₁, y₁)`, `(x₂, y₂)` 사이의 거리를

```
|x₁ - x₂| + |y₁ - y₂|
```

로 계산한다.

- 이 문제에서는 **맨해튼 거리가 2 이하인 경우**에 두 사람 사이의 경로를 확인해야 한다.
- 처음에는 `P`의 주변을 탐색하면서 `P`가 있는지만 확인하려고 했지만 주변에 `X`가 존재하는 경우처럼 **다른 경로의 존재 여부까지 고려해야 하기 때문에 좌표를 통한 단순 주변 탐색으로는 해결하기 어려웠다.**
- BFS를 이용해 실제로 이동 가능한 칸만 탐색하도록 하여 `X`가 있는 경로는 자연스럽게 제외했다.
- `visited`에는 시작점으로부터의 거리를 저장했다.
    - 시작점: `1`
    - 다음 칸: `2`
    - 다음 칸: `3`
- `visited[y]>= 3`이면 더 이상 탐색하지 않도록 하여 시작점으로부터 실제 이동 거리가 2인 위치까지만 확인했다.
- 처음에는 방문 여부를 `0`과 `1`로만 구분하려고 했지만 **시작점을 `0`으로 설정하면 방문하지 않은 칸의 값인 `0`과 시작점이 구분되지 않는 문제**가 발생할 수 있었다.
- 따라서 시작점을 `1`로 설정하고 `visited` 값을 -1하여 거리 정보로 함께 사용했다.

### 특히 어려웠던 부분

문제를 처음 읽었을 때 **"맨해튼 거리가 2인 경우도 괜찮은 것 아닌가?"**라고 생각했다. 이후 문제 조건을 다시 확인하고 **"맨해튼 거리 2 이하"인 경우를 확인해야 한다는 것**을 놓쳤다는 것을 알게 되었다.

또한 처음에는 다음과 같은 상황을 생각하지 못했다.

```
P X P
X P X
P X P
```

단순히 주변에 `P`가 있는지만 확인하면 주변의 `X` 때문에 실제로는 서로 이동할 수 없는 `P`까지 잘못 판단할 수 있다.

따라서 **두 사람 사이의 거리뿐만 아니라 그 사이의 경로가 파티션으로 막혀 있는지까지 확인해야 한다**는 점을 파악하고 BFS를 적용했다.

# 시간복잡도

각 대기실의 크기는 항상 `5 × 5`로 고정되어 있으며 각 `P`마다 최대 25개의 칸을 탐색한다.

일반적인 크기를 `R × C`, 사람의 수를 `P`라고 하면:

```
O(P × R × C)
```

이 문제에서는 `R = C = 5`로 고정되어 있으므로 사실상:

```
O(P)
```

에 가깝게 볼 수 있다.

# 어려웠던 점

- 맨해튼 거리의 조건을 **"2 이하"가 아닌 "2"로 잘못 이해**하여 문제의 조건 자체를 의심했던 것이 첫 번째 어려움이었다.
- 처음에는 시작점 주변의 배열만 확인하면 된다고 생각했지만 `X`로 막힌 경로와 그렇지 않은 경로를 구분해야 했다.
- `visited` 배열을 방문 여부뿐만 아니라 **시작점으로부터의 거리까지 저장하는 방식**으로 활용하는 과정에서 시작점의 값을 어떻게 설정할지 고민했다.
- 시작점을 `0`으로 설정하면 방문하지 않은 칸의 값인 `0`과 시작점이 같은 값이 되어 방문 여부 판단에 혼동이 생길 수 있었다.
- 이를 해결하기 위해 시작점을 `1`로 설정하고, 다음 칸을 `visited[y]+ 1`로 기록했다.

# 배운 점

- 문제를 풀기 전에 **조건의 범위와 포함 관계(`이하`, `미만`, `이상` 등)를 정확하게 확인하는 것**이 중요하다는 것을 다시 느꼈다.
- 두 점 사이의 거리만으로 문제를 판단할 수 없는 경우에는 **실제 이동 가능한 경로를 탐색해야 한다.**
- BFS에서 `visited` 배열은 단순히 방문 여부만 기록하는 것이 아니라 **시작점으로부터의 거리 정보를 함께 저장하는 용도**로 활용할 수 있다.
- 특히 시작점의 방문 표시를 `0`으로 둘 경우 "방문하지 않은 상태"와 혼동될 수 있으므로 거리까지 저장할 때는 **시작점을 `1`로 설정하는 방법**을 사용할 수 있다는 것을 배웠다.
- 앞으로 격자에서 **최단거리 + 장애물 + 특정 거리까지만 탐색**하는 문제가 나오면 BFS를 먼저 고려하고 `visited`에 거리를 함께 기록하는 방식을 적용할 수 있을 것 같다.
- 어떤 것을 기준으로 탐색할지 시작지에 대한 고민을 항상 하는 버릇을 가져야 할 것 같다.
